# 实验室计划与交付

管理者建立并发布团队月度目标，指定负责人和项目参与人员；成员关联目标，安排自己的个人任务和每周工作。周报、月报复用这些计划和实际进展，支持保存草稿、确认定稿和导出。年度目标独立记录，不强制分解到月。

## 开始使用

建议使用 Node.js 24.20.0 LTS（`.nvmrc` 与容器镜像已固定；最低兼容24.14）。

```sh
npm ci
npm run dev
```

打开 http://127.0.0.1:5173 。第一次启动时在页面创建部门管理者账号，成员随后可在登录页点击“申请加入团队”，管理者在“成员管理 → 注册申请”审批通过后即可登录。应用初始为空，不导入旧系统数据，不附带默认密码或真实员工账号。

开发模式的 API 地址为 http://127.0.0.1:4310 。数据保存到 `data/lab-planning.sqlite`，重启不会清空。开发服务默认只监听本机。

## 首次上线范围

首版面向单个部门、单实例运行，覆盖管理者与成员账号、部门项目和归档、独立年度目标、月度目标管理与审核合并发布、个人任务与周记录、月度成果确认，以及可保存、定稿、导出的管理者报告。首次上线从空数据开始，成员自行注册并经管理者审批，由管理者建立项目，再从一个月份开始建立目标和执行。

历史公司数据库、文件和账号不会自动导入。现在可在“数据导入”上传历史表格、图片或粘贴文字，配置模型后解析、校对并保存。自动报告需要管理者主动启用，AI 润色在报告页手动触发。

### 随手记录与向上汇报

侧栏「我的工作清单」持续展示本人在手事项，管理者也可用它安排自己的工作。点击「快速记录」，把领导一次交办的内容按一行一件事粘贴，预览后保存；交办人、日期和截止要求可以补充，截止未知时保留「待确认」。清单可切换领导交办、待安排、本周推进、待反馈和已完成，并记录预期交付、当前进展、下一步、优先级、预计剩余投入及需要领导决策的事项。

「安排本周」将原任务带入周计划；换周、换月不会从在手清单移除未完成任务，也不会复制出另一件任务。已有正式任务可以补录领导交办来源，任务纳入月度目标后仍保留交办信息。总体完成与本周完成分别记录。

汇报时点击「汇报预览」，展示当前筛选范围的清单，或导出 Excel 可打开的 CSV、打印为 PDF。预览和导出使用同一份当时快照，包含尚未排期的事项；与报告中心的正式周报/月报分别使用。只有本人清单进入此预览，不创建公开分享链接。

### 计划与交付

1. 管理者建立月度目标，填写项目或工作类别、预期成果、负责人、参与人员、日期与验收标准，审核后发布。成员可通过“新增临时目标”提报本人负责的临时事项，补充临时原因，提交管理员审核发布；本人草稿或退回项可修改。临时目标按月记录阶段成果，未完成时由管理员跨月承接，保留临时标记与来源。已有提报支持审核、退回和合并，来源历史保留。
2. 成员从自己参与的月度目标点击“关联个人任务”，填写个人交付；项目和人员通过目标关联，无须重复指定。普通成员仅能查看自己的个人任务和周记录，目标负责人也不能读取其他成员的个人工作。
3. 每周五北京时间 **16:00 前**，分别正式提交“本周完成情况”和“下周计划”。先更新周记录，再核对整份内容并提交；仅保存草稿或单条周记录不代表已完成周五提报。本周仍在推进的任务可以如实填写进展，无须提前标为完成。适用审核周期的成员下周计划整份提交后，由管理者通过或填写意见退回；成员按意见修改后重新整份提交，保留各次版本。
4. 系统保留截止未交事实，补交显示实际时间；后续修改需再次提交形成新版本。管理员可按状态和应交项筛选，代录、豁免及更正须填写原因并留痕。首次启用从下一个完整周开始，周中加入的成员从下周计入；历史名单不确定时先由管理员核对。
5. 管理者确认月度成果，并在报告中心生成、编辑、导出和定稿周报/月报。周提报情况作为独立管理记录，旧报告快照不随补交或目标变化。

周提报暂停与恢复从下周生效，保留原周期记录；服务重启后自动补查生效周期的遗漏。截止时间按服务端时间计算，16:00 整点提交记为逾期。当前不增加日计划。有关联目标的周草稿可在目标发布前保存，正式提交须满足目标已发布等校验；临时工作须说明原因。

计划审核与提交时效分别记录：等待审核、退回修改及审核通过不会改变原按时或迟交事实。已批准内容修改后，变更条目等待重审，未变更条目的批准继续有效；补充执行进展、成果或证据不要求重新审核计划。管理员正式下发的安排视为已确认，代录和下发草稿仍按规则审核。

管理员可填写原因删除单条周安排，保留原任务、其他周安排和历史提交、报告。删除后可沿用原任务在同一周重新安排；需要补关联月度目标时，先调整原任务关联，再建立新周安排。审核从下一个完整提报周期启用，覆盖该周期的下周计划；暂停与恢复同样从下个完整周期生效，历史暂停周期不补审。操作步骤与边界见[周计划审核与留痕删除](docs/weekly-plan-review-and-deletion.md)。已于 2026-09-21 上线：删除功能立即可用，审核从 2026-09-28 提报周期开始，覆盖 2026-10-05 起的下周计划；详见[上线记录](docs/deployment-aliyun-weekly-review-2026-09-21.md)。

## 正式运行

```sh
npm ci --include=dev
npm run build
npm start
```

打开 http://127.0.0.1:4310 。生产运行由一个服务提供网页和 API。裸机可复制 `.env.example` 为 `.env`，将其中的 `NODE_ENV` 改为 `production`，再设置监听地址、端口、数据路径及可选 AI；真实 `.env` 和数据库已加入 Git 忽略。

外网部署时使用 HTTPS 反向代理，配置 `APP_ORIGIN` 为实际站点地址、`COOKIE_SECURE=true`，数据目录必须挂载持久卷。仅在受控首次初始化时开放创建管理员页面，完成初始化后再开放给成员。

正式服务器建议使用仓库提供的 Compose 配置，完整初始化、HTTPS、可信代理、备份和迁移步骤见 [部署手册](docs/deployment.md)。

```sh
cp deploy/production.env.example .env
docker compose config --quiet
docker compose up -d --build
```

Compose 固定容器内 `HOST=0.0.0.0` 与生产模式，服务器只映射 `127.0.0.1:4310`，初始化通过受控SSH隧道进行。正式使用前需按手册切换HTTPS。当前架构适合单实例的小型部门应用；多副本部署前需迁移存储和共享会话方案。

## 汇报自动生成与 AI

无需 AI 密钥即可生成包含数据统计、实际成果、阻塞、变更和下期安排的中文报告。报告中心可配置自动草稿生成，默认关闭，时区为上海；只有启用后才按设定周期执行，同周期自动任务持久去重，不自动对外发送消息。

周报在设定的星期和时间生成该周草稿；月报选择月末最后一天时生成当月，选择每月 1 至 28 日时生成上月。服务须在触发日运行：若在同一天的设定时间后启动，会执行当日到期任务；如果停机跨过整个触发日，恢复后不会补跑错过的周期，可在报告中心选择该周期手动生成。

如需 AI 润色，在服务端配置 `AI_BASE_URL`、`AI_MODEL`、`AI_API_KEY`，再显式使用报告页的润色功能。该动作会将报告事实发送给配置的服务商；统计表和快照不会由模型改写。未配置时仍可完成生成、人工编辑、归档和导出。

## 备份与恢复

业务资料支持 Excel／CSV 导出和带版本的 JSON 迁移包；JSON 恢复需预览、匹配现有账号并确认，无冲突时保留原编号、版本、历史和报告快照。详细用法见[智能导入与数据迁移](docs/intelligent-import.md)。

```sh
npm run backup
```

脚本使用 SQLite 在线备份接口，并检查备份完整性；可在命令后指定新的输出文件路径。备份包含账号、业务数据、原始上传资料、历史、报告和模型配置（包括密钥），应与数据库一样妥善保管。业务 JSON 包不包含原始附件、账号密码或系统配置；迁移完整运行状态时使用整库备份。

恢复时先停止应用，保留当前数据库及 WAL 文件的副本，在新的目录放置已验证备份，将 `DATABASE_PATH` 指向该备份后启动。请先在独立实例核验账号、计划和报告，再切换正式实例。

## 团队自主注册

内网地址 http://192.168.0.37:4310/ 。员工在登录页选择“申请加入团队”，填写姓名、邮箱、岗位（选填）并自行设置密码。密码至少8位，允许8位纯数字，不强制复杂度。管理者在“成员管理 → 注册申请”通过或驳回；通过后启用普通成员账号，驳回需填写原因，也可再次审核。

申请通过前不能登录、查看部门数据或被分配任务。已存在的邮箱不能重复注册或覆盖密码，旧账号按原方式登录。上线与验证记录见 [2026-09-09 注册功能更新](docs/deployment-37-2026-09-09-registration.md)。
