# 实验室计划与交付

部门成员先提报月计划，管理者审核、整理并发布，成员再拆分个人周任务。周报、月报复用这些计划和实际进展，支持保存草稿、确认定稿和导出。年度目标独立记录，不强制分解到月。

## 开始使用

需要 Node.js 24.14 或更高版本。

```sh
npm ci
npm run dev
```

打开 http://127.0.0.1:5173 。第一次启动时在页面创建部门管理者账号，再到成员管理添加成员。应用初始为空，不导入旧系统数据，不附带默认密码或真实员工账号。

开发模式的 API 地址为 http://127.0.0.1:4310 。数据保存到 `data/lab-planning.sqlite`，重启不会清空。开发服务默认只监听本机。

## 日常流程

1. 成员在我的月计划里填写项目或工作类别、预期成果、责任、日期和验收标准，提交审核。
2. 管理者按项目查看提报，可退回说明原因、调整内容、审核通过，然后发布当月计划。
3. 成员从已发布且自己参与的月计划建立个人任务，填写每周承诺和实际结果。草稿允许提前准备，正式提交要求已发布的月计划关联；临时工作明确标识。
4. 管理者查看阻塞、待审核和待确认成果。发布后的范围或日期调整需要原因，原提报、发布版本和历史进展保留。
5. 报告中心按全量源数据生成周报或月报草稿，管理者补充说明、保存、导出并定稿。重新生成形成独立修订，旧报告快照不随计划变化。

周任务自报完成与月度成果验收分别统计。重点摘要不会改变全量计划数；年度进展使用独立年度记录。跨周任务保留编号，每周承诺分别记录；跨月先提报承接月计划，再由管理者关联持续任务，历史周记录保留原月归属。

## 正式运行

```sh
npm ci
npm run build
npm start
```

打开 http://127.0.0.1:4310 。生产运行由一个服务提供网页和 API。复制 `.env.example` 为 `.env` 可设置监听地址、端口、数据路径及可选 AI；真实 `.env` 和数据库已加入 Git 忽略。

外网部署时使用 HTTPS 反向代理，配置 `APP_ORIGIN` 为实际站点地址、`COOKIE_SECURE=true`，数据目录必须挂载持久卷。仅在受控首次初始化时开放创建管理员页面，完成初始化后再开放给成员。

可选容器运行：

```sh
docker build -t lab-planning .
docker run --name lab-planning -p 127.0.0.1:4310:4310 -v lab-planning-data:/app/data --env-file .env lab-planning
```

容器内需要 `HOST=0.0.0.0`；如 `.env` 使用本地默认值，运行容器时用 `-e HOST=0.0.0.0` 覆盖。当前架构适合单实例的小型部门应用；多副本部署前需迁移存储和共享会话方案。

## 汇报自动生成与 AI

无需 AI 密钥即可生成包含数据统计、实际成果、阻塞、变更和下期安排的中文报告。报告中心可配置自动草稿生成，默认关闭，时区为上海；只有启用后才按设定周期执行，同周期自动任务持久去重，不自动对外发送消息。

如需 AI 润色，在服务端配置 `AI_BASE_URL`、`AI_MODEL`、`AI_API_KEY`，再显式使用报告页的润色功能。该动作会将报告事实发送给配置的服务商；统计表和快照不会由模型改写。未配置时仍可完成生成、人工编辑、归档和导出。

## 备份与恢复

```sh
npx tsx scripts/backup.ts
```

脚本使用 SQLite 在线备份接口，并检查备份完整性；可在命令后指定新的输出文件路径。备份包含账号、业务数据、历史和报告，应与数据库一样妥善保管。

恢复时先停止应用，保留当前数据库及 WAL 文件的副本，在新的目录放置已验证备份，将 `DATABASE_PATH` 指向该备份后启动。请先在独立实例核验账号、计划和报告，再切换正式实例。
