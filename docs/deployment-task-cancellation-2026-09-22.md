# 删除周安排后的旧任务作废修复

状态：**2026-09-22 已上线并复核通过**。

## 原因与修复

一项未关联月度任务的周安排删除后，原 Task 仍为进行中并保留已有进展。原实现按设计保留 Task，概览又将无周记录的 Task 作为未排周事项计入任务总数。缺少的是明确作废整项旧任务的操作，不能从删除一个周安排直接推断整项工作不再需要。

用户已确认旧任务不再使用。本次增加管理员显式作废：必须填写原因、核对当前版本，任何未删除周安排（包括其他周和草稿）都阻止整项作废。入口位于周安排删除结果和部门概览的无周安排任务详情。

作废信息独立于任务执行状态，退出概览、工作清单、搜索、待办及督办，不记为完成；阻止继续修改、补关联、重建周安排和导入复活。任务本体、进展、删除记录、提报和报告历史保留，完整业务备份保留作废信息及操作人映射。月度目标不随任务作废。

## 用户确认的单条处理结果

新版本健康检查通过后，仅对用户明确确认的一项旧任务执行作废。操作前再次独立备份，并校验目标任务、已删除周记录、已有进展以及任务级协作记录；事务只允许更新目标 Task 并增加一条 `task/cancel` 审计。

作废后，该任务退出任务总数和未排周统计，原执行状态与历史进展保留，不进入完成数量。其他业务实体未被修改，没有物理删除任务、改写历史或发送通知。随后再次只读核对作废信息和服务健康。

## 恢复边界与证据

旧版本不识别 Task 作废信息。入口恢复尝试前即写入持久标记，此后禁止自动回退旧代码；如需修复，应使用兼容作废数据的新版本。不得用上线前备份覆盖后续真实业务。本次没有回退或恢复数据库。
