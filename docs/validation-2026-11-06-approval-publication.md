# 审批、发布与导入交互审查（2026-11-06）

## 问题与业务规则

数据导入确认生成的月度目标默认是草稿。正式生效仍需“提交审核 → 审核通过 → 确认发布”。管理员具备这三步权限；原先“我的工作清单”无论目标状态都优先提供建任务入口，详情没有明确的下一步，造成管理员找不到提交/发布操作。此次保留业务审批规则，修复操作入口与状态说明，不自动审批或发布真实计划。

## 修复范围

- 月度列表、详情、工作清单按角色与当前状态提供提交、重新提交、审核、单条发布或执行入口。提交及审核后回到更新的详情，说明尚未发布。普通成员仅可提交本人临时目标，观察者无业务写入口。
- 单条发布与全月批量发布明确分开。弹窗列出实际发布范围，补充发布仍需说明。
- 发布请求必须携带完整的目标版本清单。身份、权限、版本、状态、月份、项目状态及全部写入在同一事务内检查；缺失、额外或过期版本拒绝并回滚，避免预览后目标被修改却仍按旧确认发布。
- “待我处理”补齐月度待提交、审核通过待发布和有效委托的整份周计划审核。周审核使用与服务端审核队列相同的当前授权及整份内容验证，进入独立审核弹窗，不读取其他成员私有任务详情；分页定位及刷新/历史导航均保留正确意图。
- 非管理者且没有启用任何审核委托时，在枚举历史周计划前返回此分支，避免无意义扫描。36 个月、2160 条合成历史职责场景从约 7.36 秒降至 5.52 毫秒；有委托时保留完整授权验证。详见 `validation-2026-11-06-my-actions-no-delegation.md`。
- 导入按“处理来源差异 → 内容及完整性核对 → 确认导入”展示，按钮说明具体作用。未完成条件与提交禁用条件共用判断；未决重复来源不计为已确认排除。保存来源选择、保存核对、最终导入明确区分。导入完成提供当月目标入口，并提示新目标仍为草稿。
- 导入与审批主要按钮扩大触控区域，手机端月度操作至少 44px；没有全局放宽权限或取消完整性核对。

## 权限审查

检查月度提交/审核/发布/成果验收、整份周计划审核与负责人委托、个人成果验收、延期审批、支持请求处理、报告及周期定稿，以及导入确认。服务端继续使用当前身份和有效业务关系校验；委托撤销、负责人变化、整份内容变化、角色降级、停用及只读观察者边界有回归覆盖。未发现需要放宽权限的依据。
