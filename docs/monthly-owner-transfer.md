# 月度目标移交与页面刷新

月度目标变更主要负责人并发布后，新负责人在当前参与目标中读取最新记录；退出参与的成员可从“历史记录”查看有权访问的旧快照。历史行和详情明确标注只读及当时的负责人、状态，不再计入当前目标、已发布数量及本月趋势。

负责人仍是协作者时，继续拥有当前参与权限。关联的有效个人任务（包括已完成但未作废的任务）仍要求其负责人留在参与名单；已作废任务保留历史，不再阻止移交。不同编号的同名目标不会自动合并，发布原件与审计历史也不会被重写。

工作空间列表在页面可见且联网时每 45 秒重新读取，也在重新聚焦、恢复可见和恢复网络时读取。后台更新保留已打开的编辑表单；读取失败保留当前数据，权限失效则清除列表。失效分页游标自动回到第一页，不会把详情引用当成列表记录。直接设置与审核表单沿用显式读取。

页面身份绑定到后续业务 API 请求。同一浏览器其他标签页切换账号时，服务端拒绝身份不匹配的请求，客户端清除旧读取环境并重读身份，不会自动重试写入。正常的目标改派不会重建账号或覆盖草稿。

发布后，已经打开的旧页面需要刷新一次以加载新代码，之后自动刷新机制生效。

验证覆盖服务层的当前/历史归属、历史深链与授权、当前统计、有效及作废任务、读取失败、失效分页、身份切换和原始历史保护。合成账号浏览器验收覆盖另一会话改派后的两端自动更新、已打开详情转历史、未保存草稿保留及移动布局。正式环境验证仅使用只读数据源和隔离内存副本；部署记录与内部证据保存在受控运维目录。
