## 浏览器验收

使用隔离内存数据库、虚构成员与主管账号、仅监听本机的 API/Vite 服务。工作通知与原生外发环境开关关闭，未启动任何发送 worker。操作顺序：

1. 成员打开任务，分别看到任务截止与催办回应期限；“同时回应”初始未选。
2. 保存实际进展，原催办仍待回应。再次填写进展并明确勾选回应，催办结束，任务仍为进行中，没有产生正式周提报。
3. 成员提出延期后原截止不变；退出并以主管登录，批准后才更新截止，保留申请与处理意见。
4. 主管选择两项工作，按一位成员生成批量预览；展示要求、期限与当天额度，确认后出现两项待回应事项。
5. 管理通知从“我的工作与消息”进入摘要，再进入原任务处理面板；入口保留摘要目标类型。
6. 通知设置的规则预览成功返回当前风险；未配置的原生能力不能启用。诊断如实显示本地测试未配置的外发、备份、心跳状态。
7. 390×844 手机视口检查工作台与任务表单，页面和文档宽度均为 390，无整页横向溢出；详情栏目换行，底部保存按钮可滚动触达。桌面 1280×720 批量预览可读取并确认。
8. 更新 API 后用独立合成历史数据再查详情：延期摘要显示原截止、已批准及当前截止；回应摘要显示当次验证结果与下一步。没有使用后续进展替换原回应事实。
