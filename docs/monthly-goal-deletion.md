# 月度目标删除与重复项处理

## 问题与决定

退回表示仍需修改并重新提报，不能表达重复目标不再执行。现有合并会生成第三条目标，也不适合保留已导入目标、移除成员重复提报。因此新增独立的「删除目标」，不以退回或合并替代删除。

- 管理员可删除从未发布的草稿、退回、待审核、审核通过待发布目标；审核窗口可直接转入删除确认。
- 成员可删除自己负责的临时草稿/退回目标。历史普通自提目标须存在本人创建审计且非导入来源；管理员分配或导入的普通目标由管理员维护。无创建证据的旧记录交管理员处理。
- 已发布、已合并、有发布历史、实际成果或未处理关联的目标禁止删除。有效任务、周安排及承接/合并关系须先处理，删除不级联、不自动挪动成果。

## 数据与接口

保留目标原 ID、业务状态、来源及版本历史，当前版本递增，追加 `deletion: {deletedAt, deletedBy, reason}`，写入 plan/delete 审计。`isActiveMonthlyPlan` 是当前业务使用条件。删除事务重新验证当前身份、版本、状态和依赖；过期预览不得删除新版本。已作废的无成果任务和已删除且从未正式提交的周草稿可作为历史保留，不阻断删除；已提交或有成果的历史仍阻断。

`GET /api/plans/:id/deletion-preview` 返回最新目标、canDelete 和 blockers；本人可了解被阻止原因，无关成员/观察员不可访问。`DELETE /api/plans/:id` 必须提供 version 和非空 reason。

月度页提供独立「已删除」视图与只读历史。普通列表、计数、待办、工作清单、年度统计、导入及排周候选均排除已删除目标。旧链接显示删除状态，不保留任何写入口。历史权限投影携带删除标记，防止旧快照重新成为可操作目标；历史内容按原权限脱敏。

## 来源与历史

钉钉来源账本及普通导入结果保留，重新获取不得把删除目标当新增或重新发布。原来源关联的目标已删除时要求人工排除该来源并核对保留目标，不自动重绑账本。本期不增加恢复或成果迁移功能。

既有发布、报告快照和审计保留。完整业务导出保留删除字段并映射删除人；恢复检查时间、状态与有效任务/周安排引用。业务迁移包原有来源账本限制不变，完整 SQLite 备份仍是完整恢复依据。

## 验证与上线

覆盖角色/来源/状态矩阵、版本竞争、删除依赖、所有写入口拒绝、列表统计和候选消失、已删除视图/旧链接、导入不复活以及迁移往返。浏览器只操作独立合成数据，生产真实目标不代删。

删除字段无需数据库结构迁移；但是旧程序不识别删除标记。产生第一条真实删除记录后，不能直接回滚到不支持该字段的代码，否则目标会重新显示。上线前后须备份并验证，后续回滚需采用支持删除语义的版本，不能以恢复旧数据库覆盖业务写入。
