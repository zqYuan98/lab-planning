## 问题及修正

| 问题 | 根因 | 修复行为 |
| --- | --- | --- |
| 管理员找不到本人周提报 | 周初名单仅纳入 member，个人卡片也被管理角色条件隐藏 | 管理员与成员均有本人完成情况、下周计划两项职责；管理统计和代录能力保留 |
| 首位管理员被显示为待审批，无法添加周任务 | 提报关联账号查询把缺省 registrationStatus 转成 SQL null，前端判为不可用 | 统一缺省已批准账号语义；观察者仍无提报义务 |
| 全部周期看板提前显示完成，跨月任务不再逾期 | 直接取最近一条周状态，把阶段 done 当成整个任务完成 | 全部周期按总体任务状态及最近有效执行显示，未来安排不覆盖现状；阶段 done 不抹除未结束任务的逾期 |
| 选择新月份后旧未完成任务消失 | 所选周期只查询本期周记录、所属月目标任务及到期任务 | 增加“包含往期未完成任务”选项，补入旧任务并标记；按任务 ID 去重，不改变历史归属或自动生成承接目标 |
| 新月目标未拆任务时看不到 | 看板只统计个人任务/周记录 | 顶部独立显示当月目标数量、已发布数量和待拆解目标入口，目标不伪装成任务计数 |
| 跨月承接后原目标又要求重新建任务 | 原任务迁移后，来源目标失去当前 task.monthlyPlanId 关联 | 已证明迁移的来源目标显示“已跨月承接，原月待验收”，退出待安排并移除重复建任务提示，仍保留原月成果与验收入口 |
| 孤立周记录或旧导入完成状态使总体完成数失真 | 无总体任务证据，或导入 done 缺少本人完成确认 | 显示总体状态待核对；导入完成待核对与个人工作清单采用同一判断，确认前继续保留在手及逾期事实 |

## 统计范围

- **全部周期**是个人任务总台账，包含历史未完成及已完成任务，默认不显示停用成员、待审批账号与作废任务。当前任务归属使用当前月目标；月度目标本身单独统计。
- **按月/按周**保留所选周期的周阶段事实。可勾选纳入往期未完成；没有本期周记录的旧任务显示未排周，并在任务明细、看板显示总体状态。
- 全部周期的完成数只包含明确结束的整个任务。历史周期的阶段完成仍保留，不等于整体完成、整份周提报或月度验收。
- 逾期以当前任务截止日和当前上海日期计算，月周视图不是历史状态快照。正式期末复盘使用“历史周期复盘”。
- 新月份发布不会自动复制、完成或迁移旧任务。正式跨月执行继续使用已有承接流程，沿用任务 ID，并保留已提交历史周记录。

## 管理员职责启用边界

已有系统在首次读取/协调提报规则时持久化管理员生效周：当前周期尚未截止时从当前周起，否则从下一完整周起。不追补升级前已截止周期的管理员缺交。当前自动冻结且未截止、未人工确认的名单只修复一次；人工名单保持原决定，历史不明时由管理者核对。全休周、暂停周期、周中加入和角色变化仍遵循原周期规则。

规则生效周及名单修复标记随业务导出恢复保留。未使用默认规则升级后的恢复资格也有回归验证。管理员本人提醒与部门汇总均有模拟投递验证；本人完成提报后不继续催交该项。

## 承接证据

来源目标的已承接标记使用共用只读查询，仅认可已完成 apply 且实际迁移了任务，或同一任务的有效 relink 审计证明它迁入来源目标的承接后继链。仅创建草稿、发布目标或在新目标下创建另一任务不会误判。标记不替代原月验收，不改变业务对象与历史快照。
