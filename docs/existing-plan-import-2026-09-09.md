# 已有月周计划直接导入生效

用户指出：历史资料解析必须能进入实际月计划和周执行，不能强制把已有资料当新提报，要求成员重复走提报流程。

## 本次行为

- 新上传页面默认“导入已有计划”。管理员校对后一次确认即可生效，月计划为published、周记录为submitted；不生成虚构的成员提交或审核通过事件。
- 成员可以解析和校对自己的已有资料，交管理员一次确认。管理员可以直接导入自己整理的整部门资料，不需要先让每位成员提交。
- 保留“生成新计划草稿”和“仅存历史资料”，分别适用于新提报和单纯归档；原批次可以切换处理方式，已保存批次可复用原文件继续整理。
- 已有月计划最低需要事项、有效负责人、月份；已有周记录最低需要事项、有效负责人、所属周。原表缺少的预期成果、验收标准、截止日期、类别不补造，保留空值。周记录没有明确月计划关联时保持未关联，并保留导入来源，不虚构临时工作原因。
- 旧实际成果和原状态保留。月度成果有内容时先记录为待验收；管理员也可明确指定已验收，必须有实际成果。原文“完成”不由模型自动变成管理者验收。计划本身生效不以再次提报或成果验收为前提。
- 来源标识进入月计划、任务、周记录及业务导出。后续修改导入记录时也允许保留原表缺项；普通新计划继续使用原有完整字段和审批规则。
- 同一来源草稿转换为已有计划时沿用原ID；已经手动修改的草稿冲突阻止覆盖，已经生效的来源跳过。新增、草稿转生效、跳过分别计数。
- 月周记录、来源关联、审计和月份发布快照事务保存。导出与恢复兼容这些缺项和来源标识，并继续严格过滤未知字段和密钥。

## 验收

隔离浏览器使用内存数据库、本地模拟模型及合成资料，完成：

1. 缺预期成果、验收标准、精确截止日的资料解析 → 直接确认生效 → 跳转月度计划详情，显示原实际成果和“已生效”，草稿/待审核数量均为0。
2. 修改导入月计划标题，其他缺项继续为空，保存成功且生成修订版本。
3. 没有原月计划关联的旧周工作导入 → 周执行显示已有计划导入、未关联月计划、原状态及成果。
4. 成员自行导入 → 交管理员确认 → 管理员筛选待确认批次 → 一次确认 → 成员月计划生效。

浏览器错误/警告日志为空。自动测试覆盖原业务规则、直接生效、幂等、草稿转换、权限、缺项编辑、事务回滚及导出恢复；最终数量以上线记录为准。

没有使用用户真实数据进行这些验证，没有代用户将当前正式批次生效；管理员在上线后自行选择已有计划方式确认保存。
