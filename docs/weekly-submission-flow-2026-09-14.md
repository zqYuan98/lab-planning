# 周提报状态与跳转修复（2026-09-14）

## 问题与原因

正式库只读核验确认：反馈成员的9月14日当周有3条已纳入周统计的记录，其中2条已填进展，9月21日当周没有记录；整份提报回执为0。原界面同时使用“提交周计划”和“待提交”，没有呈现已保存内容、最近更新时间及明确的内容周，容易把单条保存、本周安排与下周整份计划混淆。

更直接的入口缺陷是 `WeeklySubmissionPanel.open` 无条件调用 `crypto.randomUUID()`。正式站使用内网HTTP，浏览器 `isSecureContext=false`、`crypto.randomUUID=undefined`，造成查看、正式提交入口报错。此前localhost属于浏览器安全环境，未覆盖这一部署差异。

## 修复

- 使用HTTP环境可用的 `crypto.getRandomValues` 生成UUID，仅正式提交生成请求编号；一次确认保留同一编号以支持幂等重试。
- 管理者和成员均显示已保存项数、已填进展/计划项数、草稿数、最近更新时间，整份提交时间单独显示。未提交者显示“已填写，待整份提交”等具体状态；不回填或伪造提交回执。
- 本周完成情况和下周计划各自明确起止日期。截止周期在父页面受控；选提报内容后定位到准确的成员及内容周，同时清除旧搜索和状态筛选。
- 详情直接展示当前记录；预览缺项可跳入对应记录编辑，保存后保留返回整份核对的入口。新建及顺延记录也保留归属，并让管理员创建时沿用选中的成员。
- 单条按钮改为“将该条纳入周统计”，与“确认提交整份内容”区别。历史展示固定提交快照；版本冲突后可以刷新重新核对，重置旧错误提示。

本轮沿用原有服务端整份校验、截止、缺交、补交、豁免与修订规则；填写记录不会自动伪造整份提报，日计划未加入。
