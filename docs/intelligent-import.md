# 智能导入、历史资料与数据迁移

## 使用流程

1. 管理者打开 **数据导入 → AI 模型设置**，填写兼容 OpenAI 的服务地址（通常含 `/v1`）、文本模型、视觉模型和密钥。视觉模型留空时沿用文本模型；需要识别图片时该模型必须支持图片输入。点击“测试连接”验证 JSON 文本调用；这一步只发送合成 ping，不发送业务资料。
2. 上传或直接拖入 XLSX、CSV、TSV、TXT、PNG、JPG 或 WebP，单文件不超过10 MiB；支持多文件逐个保存，每个文件独立显示结果。点击上传区域后可用 Ctrl / ⌘ + V 粘贴截图，“粘贴内容”仍支持表格和文字。XLS 需先另存为 XLSX，尚不支持 PDF、加密工作簿或自动下载钉钉链接。
3. 勾选工作表，按资料选择月度或每周内容。原表没有明确周期时，可以补充参考周期；填写解析说明后开始解析。所选内容会发送至配置的模型服务。
4. 查看后台进度。大表每段最多20源行，携带原表头及周期上下文；原始文件和已完成的解析片段持久保存。服务重启或模型失败后可重试；需纠正模型结果时勾选“重新调用模型”，避免复用旧解析。
5. 逐条核对或批量匹配人员、项目、工作类别与月计划。每次保存校对都会保存到批次；尚未匹配的人名与项目名保留原文，不自动创建可登录账号。
6. 新上传批次默认选择 **导入已有计划**。管理员核对后点击“确认并生效”，记录直接进入对应月份的月度计划或对应周的每周执行，原有实际成果一起保留。成员可以上传、解析、校对自己的计划，点击“交管理员确认”；管理员在导入批次中勾选“待确认的已有计划”完成一次确认，成员无需再到月计划重新提报。

也可选择 **生成新计划草稿** 或 **仅存历史资料**。新计划草稿沿用提报流程：月计划仍需提交、审核和发布，周记录初始保持未提交；历史资料用于检索、查看、纠正与导出，不自动进入工作计划。

已有计划只需核对事项名称、负责人及所属月份或周。原表未注明的项目、类别、预期成果、验收标准或截止日期保留为空，无需为导入补造信息；原本没有月计划关联的周记录显示“未关联月计划”，不会虚构成临时工作。已有计划生效后，编辑原表缺失的非必要字段也可继续留空。

导入前可以逐行查看将进入的月份或周、原文状态、实际成果和系统状态。月计划已有成果默认保留为“成果已记录，验收待确认”，没有成果时不虚构；原文“完成”不会自动成为“已验收”，已验收状态由管理员明确选择。周执行状态按原文明确的完成、未完成、进行中、受阻等状态识别，并可在校对时修改。这个成果验收状态不会阻止已有计划本身生效，也不要求成员重新提报计划。

交管理员确认后，成员仍可修改校对结果；保存修改会清除原确认申请，需再点击一次“交管理员确认”。确认成功后，结果列表提供“打开月计划”或“打开周记录”，直接进入对应记录及周期。

## 将临时交办事项加入计划

在待确认批次中点击“校对”，先通过“纳入计划”选择月度计划或每周计划，再把“任务性质”设为“临时交办”，填写临时原因或交办说明。领导的临时安排、应急支持等可以在这里记录；不会仅凭没有项目或月目标关联就自动标记临时。

- 月度临时事项保存为临时月度目标；每周临时事项保存为临时个人任务和对应周记录，可以暂不关联月度目标。临时周新任务不能同时关联月度目标；目标发布后拆出的周任务按目标内工作管理。
- 可以对勾选记录批量设置任务性质及说明，预览中会显示临时标记。引用已有个人任务时沿用该任务的性质和原因，导入不会重新分类或覆盖原任务。
- “保存校对”可暂存缺项；正式加入计划前必须填写临时说明与对应周期。“导入已有计划”由管理员确认后生效，成员仍需交管理员确认；“生成新计划草稿”允许成员生成本人的临时月度目标和临时周任务，后续流程与页面直接创建一致。
- “仅存历史资料”保存原始临时属性和说明，允许资料缺项。JSON 业务导出、恢复以及表格导出保留这些属性，原文及审计记录继续保留。

## 钉钉历史表格的处理

当前支持从钉钉导出的本地表格，不含钉钉在线直连或双向同步。

已针对用户提供的研发历史表做只读结构验证：周表444行、月表186行，共630非空源行。合并单元格及不同表头保留，按20行分为33个模型请求片段，源行覆盖完整。周表同一行有本周和下周不同日期区段；月表存在多月分节和新旧两套模板。模型指令要求区分这些内容，不能用一个日期覆盖全表。

上述验证证明文件读取和分块没有遗漏，不代表真实模型已成功提取所有事项。界面会列出未生成候选的源行（其中包含表头和日期行），供对照原表核验。没有明确年份、验收标准或月周关联时保留空值，不能编造。

## 重试、重复和纠正

- 相同用户重复上传相同内容返回已保存批次。保存后可用“继续处理此文件”复用原文件，处理其他工作表、未选条目，或将原资料整理为已有计划或新草稿。
- 同一来源已经生成的新计划草稿，改为“导入已有计划”确认时沿用原计划编号转为生效记录，避免要求成员重新提报或重复创建计划。
- 同一来源批次下相同来源项再次保存会跳过；界面分别显示新增和跳过数量。另一个管理者接手同一来源批次也不重复创建。
- 已导入来源项的内容发生变化时返回冲突，要求在原历史记录或原计划中纠正，不会显示保存成功而忽略修改。
- 历史纠正须填写原因，保存修改前后内容和版本；原始文件及原始文本保留。纠正历史资料不自动改写已生成计划或报告。
- 不同内容版本的 Excel 属于不同来源，目前不支持仅靠模糊标题跨文件自动更新已有事项。需要先核对重复；没有宣称具有跨版本 Excel 自动合并能力。
- 一次确认的月计划、任务、周记录及关联按事务保存。任何一项失败时该次写入完整回滚，预览资料仍在。

## 删除导入批次与历史资料

- 打开批次后点击“删除批次”，核对确认框中的范围后删除。批次所有者或管理员可操作；解析中的批次需等解析结束。删除批次会清除该批次及其归档历史资料，原文件在没有其他批次引用时清理。
- “已保存历史资料”的每行和详情页均提供删除入口，可单独删除一条历史资料，保留来源批次、原文件与其他行。管理员、导入者或该资料的负责人可按权限删除。
- 删除保留已生成的月度目标、个人任务、周记录和已保存报告，并记录审计。已经保存的来源保留必要去重信息，重复确认不会重新创建被删除的归档历史，也不会复制已有正式计划。
- 删除确认使用当前记录版本；他人修改后须刷新重试。取消确认不改变数据。

## 导出和恢复

所有账号可导出自己有权查看的数据。支持全部资料或项目、年度目标、月计划、任务、周记录、历史资料分类导出；API 还支持 month、ownerId、projectId 筛选。

- **Excel／CSV**：用于查看、筛选和整理；保留编号与时间。Excel 会把超长文字拆为后续列，不静默截断。
- **JSON 业务数据包**：含格式版本及必要关联记录。管理者完整导出包括业务审计、发布版本和报告快照；排除密钥、令牌、会话、密码和账号审批信息。
- **恢复 JSON 包**：管理者上传不超过32 MiB的包，按邮箱或明确映射关联已建立的账号；预览显示缺项、冲突、新增和跳过。确认前再次校验数据是否变化，存在冲突时不覆盖，写入失败整体回滚。相同已有记录跳过，保留源编号、版本、时间及固定报告快照。
- **完整 SQLite 备份**：用于连同原始附件、导入批次、账号及配置迁移。JSON 包只保留历史资料的来源标识及原文，不包含原文件；恢复后原文件下载入口可能不可用。

业务 JSON 恢复实际新增/替换数据时，同事务更新浏览器命令环境；仅预览、全部跳过或恢复失败时不更新。跨月承接回执和命令环境不包含在业务包中。完整 SQLite 恢复、克隆或回退后，启动前必须对恢复副本执行 `npm run reset-operation-context -- <恢复库路径>`，再刷新页面核对未确认的承接操作；步骤见[部署手册](deployment.md#更新备份与恢复)。

数据库新增迁移登记 `schema_migrations`。版本1登记既有JSON存储格式，不重写旧业务记录；拒绝用不支持的新数据版本启动。未来业务结构变化仍需增加明确迁移代码与副本核验，不能承诺任何未来规则变化都能自动推断缺失信息。

## 模型配置与运行边界

管理员保存的模型配置优先于环境变量；兼容原来的 `AI_BASE_URL`、`AI_MODEL`、`AI_API_KEY`，增加 `AI_VISION_MODEL`。保存过的密钥不回显到网页，也不进入业务导出或审计。报告润色复用该配置。

后台请求使用 `/chat/completions`，包含 `response_format: {type:'json_object'}`，最大输出8192 tokens。所选服务需支持这些兼容参数及对应模型；图片通过 `image_url` 的 data URL 发送。单次模型请求超时60秒，失败可以复用已完成片段重试。连接测试不代表视觉模型或实际历史资料的识别效果已验收。

每个账号最多同时运行2个解析任务。权限、账号状态或集成令牌被撤销后停止后续分块请求。部署当前仍为单实例；不要启动多个应用进程共同处理同一个数据库。

外部智能体接口见[集成 API](integration-api.md)。


## 2026-09-11：月度目标权限与周提报迁移

普通月度目标由管理者建立与维护。自 2026-09-17 起，成员可在月度目标页或导入中建立本人临时目标草稿，由管理员审核发布；“新草稿”导入中的普通团队月度目标仍由管理者创建。成员可整理自己的历史资料、已有计划确认申请和个人周记录。成员批次中若有后来划归他人的条目，只能查看、校对和提交自己的部分，隐藏部分留给管理员继续处理。

普通成员导出仅包含自己的任务和周记录，以及有权查看的目标信息；参与同一目标不会授权导出他人的个人任务。历史或关联用途的目标投影不能作为完整目标恢复，完整迁移须使用管理员导出包。

业务 JSON 格式 v2 增加周提报规则、冻结名单、整份提交版本、截止缺交与豁免更正记录。成员包不包含部门配置和完整名单，恢复个人提报事实需要目标系统已具备匹配周期。v1 包仍可恢复，但不会凭历史周记录补造按时提交事实。数据库 `schema_migrations` 版本与业务包格式版本是独立概念。

正常启动的新系统会自动建立默认周提报规则。仅当默认规则从未配置、尚无周期或提报事实时，恢复预览允许明确列出的规则替换；已有业务规则仍按冲突处理。新周提报时间须保持系统导出的 UTC 毫秒格式，不能手工改成其他时区表示。替换保留来源历史，并在提交前重新校验，写入失败会整体回滚。

周计划审核与留痕删除继续使用现有 v2/v3 业务包格式，补充可选审批/删除元数据和默认空的审核集合。完整导出保留已删除周安排、同任务同周的新安排、审核回执和冻结上下文；恢复仅对未删除行检查同任务同周唯一性。账号映射也会更新删除人、审核人和计划指纹中的责任人。旧包缺少审批元数据时，适用当前规则的成员自报、代录及下发草稿在预览中列为待审核；已正式下发安排和历史快照保留原语义。旧规则没有审批生效周时，继承目标已保存的边界并提示。暂停标记须符合当前周期窗口，当前批准不能引用已作废的回执，历史报告和审计仍可保留作废前事实。恢复不生成新通知或外发投递，操作说明见[周计划审核与留痕删除](weekly-plan-review-and-deletion.md)。
