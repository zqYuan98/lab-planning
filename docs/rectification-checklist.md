## 四、产品方向（AI native）

不属于整改，是下一阶段的建设项。每项先在一个页面上试，用真实任务走查后再推广。

| 编号 | 事项 | 验收标准 |
| --- | --- | --- |
| A1 | 一句话录入 | 成员写一句话，系统拆出状态、阻塞、需要的支持、下一步，成员只确认；录入一条进展的输入框从多个降到 1 个 |
| A2 | 首页给结论 | 首页主体是“需要你处理的 N 件事”，每条带原因和一键操作；指标卡降为次要信息 |
| A3 | 规则由系统执行 | 截止时间、审核范围、统计口径不再写在页面上，只在与当事人有关时提醒 |

## 五、防止复发的检查点

- 每次合并前：`npm test`、`npm run lint:design`、`npm run lint:docs`、`npm run build`。
- 每次界面改动：前后截图加一次真实任务走查。
- 每月回看一次 `design-system/baseline.json`：数字应当下降。没有下降的指标，对应的待整改项提到最前。
- 同类问题出现第二次：按 `.claude/skills/retro` 复盘，优先做成自动检查。
