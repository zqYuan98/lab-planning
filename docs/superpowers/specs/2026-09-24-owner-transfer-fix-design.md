# 月度目标移交修复

用户在核查报告后明确要求“修复上线”，本规格收敛已确认问题的修复与验收，不改变目标、任务和历史记录的业务归属。

## 行为

月度目标默认展示当前参与记录。已退出目标的成员通过历史参与入口查看有权访问的旧快照，行和详情明确标注历史、只读，不混入当前目标与成果统计。管理者继续查看当前部门目标。历史发布原件和审计记录保持不可变，历史详情链接继续可用。

页面查询在前台合理间隔、重新聚焦、回到前台和恢复网络时重新读取。多个触发合并，避免重复并发请求。后台重新读取保留已有列表和已打开的编辑表单；不重新挂载整个应用，不改写未保存内容，保存仍通过版本校验防止覆盖他人变更。分页数据变更时恢复有效查询，不让旧游标使页面永久陈旧。

分页查询为空或失去权限时，不允许把详情引用重新填入列表和统计。同一浏览器的其他标签页切换账号后，请求必须校验页面所绑定身份；身份不匹配时先清除旧读取环境再重读身份，不能在旧账号抬头下显示新账号数据。正常负责人变更不触发账号重建。

月度目标移除参与者的校验只考虑有效个人任务；已作废任务保留原有数据和历史，不阻止移交。有效任务（包括已完成但未作废的任务）仍要求负责人作为目标参与者，避免破坏关联。

本次不将同名不同编号的目标自动合并，也不修改任何正式业务数据。新建同名目标的提醒作为后续体验改进，不作为本次纠正交接行为的前提。

## 验证与发布

回归覆盖原成员、新负责人、保留为协作者、月度默认/历史筛选、直接历史链接、个人概览、历史发布不变、后台跨会话刷新、请求去重、隐藏页面、失联恢复、退出和身份变化、作废/有效任务移交。

通过类型检查、构建、针对性测试及 Linux 全量测试后，使用正式数据只读副本核验当前/历史归属；界面使用隔离数据验收。发布前在线备份并验证完整性，维护窗口切换新代码，保留运行配置和业务实体字节。上线后检查服务、正式入口、静态资源和身份读取。不得恢复旧库覆盖上线期间新增数据。
