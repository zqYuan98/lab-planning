# 团队注册与审批

用户已明确要求成员自行注册、管理员审批，密码至少8位。本次沿用现有页面和账号模型，不增加邀请流程或企业认证。

- 已初始化系统的登录页增加“申请加入团队”：姓名、岗位、邮箱、密码、确认密码。密码8至256字符，不强制数字或复杂度；所有创建/重设密码表单共用此边界。
- 注册固定创建普通成员、未启用、待审批的账号，不接受客户端角色/启用/审批字段，不发登录会话。未初始化系统禁止注册，保留首次管理员初始化流程。邮箱唯一，重复申请不能修改现有密码。
- User增加可选registrationStatus（pending/approved/rejected）及审核说明。旧账号缺少该字段时按既有启用规则工作，无需批量改库。
- 管理员在成员管理看到待审批数量和申请列表，可通过/驳回并留说明；驳回需说明。通过后固定普通成员并启用，之后可走既有账号管理。驳回后可由管理员重新审核，不提供匿名覆盖申请资料的接口。
- 审核API仅管理员可用，按版本校验事务提交与审计；普通账号编辑接口不能绕过注册审核。审批前/驳回后不能登录或读取业务数据；正确密码登录时显示明确状态，错误密码仍使用统一失败信息。
- 普通成员的通讯录、报告快照不包含未通过的申请。安全用户响应及审计不包含密码哈希。注册端点受现有来源/JSON限制和独立IP限流保护。
- 测试覆盖8位接受/7位拒绝、固定权限、会话隔离、未审批访问阻断、审批/驳回/重复请求/版本冲突、管理员专属权限、旧账号兼容和限流。浏览器验证注册到审批流程使用隔离数据库。
- 更新37前备份，构建新版本并隔离验证；使用原持久卷切换，保留旧镜像与代码用于回退。本机正式服务保持停止。

- 审核仅接受 pending/rejected 状态；禁止通过此接口重新审核旧账号或已通过账号，避免绕过既有角色与最后一位管理员保护。
- 回退限制：旧镜像不识别注册状态。产生新申请后禁止直接回退旧代码并复用当前库；应发布兼容修复版本，或在保全更新后数据并确认恢复范围后恢复上线前备份。
