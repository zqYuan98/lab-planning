## LP-01 月度未完成原因

现状：`server/domain-plans.ts:197` 已有版本保护、事务和审计；缺口是未完成结论的说明校验。`src/pages/Monthly.tsx:608` 表单缺少动态必填。

沿用 `POST /api/plans/:id/result` 和现有字段。结论为 `not_completed` 时，`acceptanceNote` 去除首尾空白后必填；`actualOutcome` 可空。结论为 `submitted/accepted` 时沿用实际成果必填规则。第一版不增加原因分类。

前端切换为“未完成”后将标签改为“未完成原因”，同步 required 和错误提示；切回其他状态保留已输入内容。后端独立校验，错误返回 400 和对应字段提示，目标版本、审计、通知均不产生变化。有效写入继续与审计同事务提交。

历史空原因保留并标记“历史说明缺失”；再次确认未完成时必须补齐，不自动填充模板文字。现有成果确认权限不改变。

## LP-02 跨月字段继承

现状：`MonthlyService.carry()` 已在事务中嵌套 `create()`；来源三字段没有进入 `create()` 的入库白名单。不能把此问题描述为没有事务。

| 处理方式 | 字段 |
| --- | --- |
| 继承 | title、projectId/category、ownerId/collaboratorIds、expectedOutcome、acceptanceCriteria、priority、isTemporary/temporaryReason、workSource/assignedBy/assignedOn |
| 本次明确填写 | month、dueDate、承接原因；后续向导可编辑剩余工作描述 |
| 指向来源 | sourcePlanId 指直接来源目标，来源历史通过链路查询 |
| 新目标重置 | id/version/createdAt/updatedAt、status=draft、publishedVersion=null、reviewComment、actualOutcome、acceptanceStatus=pending、acceptanceNote、合并信息 |
| 不复制 | importSource、历史验收/发布记录、旧操作回执 |

普通创建补全交办字段的标准校验和保存。原公开创建接口不再接受非空 `sourcePlanId`，也不允许普通编辑修改它；承接改用私有白名单创建函数，防止绕过来源版本和幂等检查。可信导入/恢复继续通过专用服务校验历史引用，不通过普通创建伪造承接。

保留来源资格检查：不承接已合并、已验收完成或不符合跨月关系的目标。来源项目归档、负责人/参与人不可分配时，明确提示先处理人员或项目，不静默删人。新目标仍需按原流程审核发布；原目标的成果和快照不回写。

## LP-03 跨月承接命令

接口仍为 `POST /api/plans/:id/carry`，请求约定：

```json
{
  "requestId": "客户端生成并在不确定重试时复用的 UUID",
  "sourceVersion": 7,
  "month": "2026-10",
  "dueDate": "2026-10-23",
  "reason": "剩余联调工作承接至下月"
}
```

`requestId` 采用当前周安排命令已支持的 16～100 位字母、数字、下划线或连字符规范；客户端诊断号另由服务器生成。保留当前响应 `MonthlyPlan` 形状，附加响应头标识是否回放即可，不强制所有调用方迁移响应封装。

新增内部回执集合 `monthlyCarryRequests`，记录 `actorId、requestId、sourcePlanId、sourceVersion、payloadHash、targetPlanId` 和实体时间。唯一键由操作类型、操作者、requestId 确定，禁止“来源＋目标月份唯一”，因为同来源可明确拆成多个承接目标。

事务顺序：

1. 校验活跃身份、管理权限和请求格式，生成规范内容指纹。
2. 查同一操作回执；不同内容返回 `409 IDEMPOTENCY_MISMATCH`。相同内容重新核对目标可读性后返回已创建目标，不重复创建和审计。
3. 首次请求核对来源当前版本，不符返回 `409 SOURCE_VERSION_CONFLICT`；随后核对来源资格、日期、项目和人员。
4. 白名单创建承接草稿，写创建/承接审计和回执，原子提交。

回执重放早于来源最新版本校验，否则首次成功后来源变化会让合法重试失败。回执中的目标后来被合并等变化时返回当前状态并提示核对，不能自行创建替代目标；回执目标缺失则返回明确冲突，不自动修复。

前端打开承接表单时锁定来源版本，保留稳定提交尝试 ID。双击禁用是体验保护，接口幂等仍为最终保证。网络结果未知时复用原 ID 和原请求；内容变更需建立新尝试，原尝试须先核对结果。修改月份或重新确认最新来源后生成新 ID。另建同月目标需显式选择“拆分承接”，先显示已有承接记录，减少误把新尝试当成新业务。

回执进入整库备份，不进入跨环境业务包。业务恢复或切换实例时客户端操作草稿必须失效：初始化返回持久化的 `operationEpoch`，命令草稿记录该值，承接请求通过 `X-Operation-Epoch` 请求头提交，缺少或过期返回 `409 OPERATION_CONTEXT_CHANGED`；不接受客户端自选 epoch。业务恢复/克隆后更新 epoch，普通服务重启保持不变。旧 epoch 请求拒绝并要求核对已有目标；恢复接口不能仅依靠丢失回执后的新 requestId 重建对象。同环境完整备份同时恢复目标与回执；灾备恢复到较早快照也要更新 epoch，防止恢复点之后的旧浏览器命令重放。

## LP-04 统一基础校验

在基础工作服务增加 `validateWorkChange(before, normalizedPatch, context)`，复用既有字段校验，所有工作入口在写入前调用。`context` 由服务端指定，区分普通修改、可信历史导入和完整恢复；客户端不能传入“绕过校验”。

| 对象与操作 | 一致规则 |
| --- | --- |
| 整体任务标为 done | completionNote 必填，清除 waitingForFeedback；仅有证据链接不能代替完成说明 |
| 整体任务标为 blocked | blockerReason 必填；首次正式报告阻塞还须填写 blockerImpact、supportNeeded，可明确填写“暂不需要支持” |
| 周执行标为 done | actualOutcome 必填；只代表该周阶段完成 |
| 周执行标为 blocked/not_done | blocker 必填；正式报告阻塞还需说明影响与支持诉求 |
| 明确“同时完成整个任务” | 周记录及任务版本同时匹配，分别满足完成校验，同事务保存 |
| 整份周提报 | 继续执行既有完整性、月发布、归属周、审核和快照版本要求 |

任务没有独立草稿状态；上述 task 状态写入即为正式业务修改。周记录可保存 planned/doing 的未提交草稿；若主动保存 done/blocked/not_done，基础成果/原因仍必填，影响和支持详情在正式阻塞提报前补齐。不得因 UI 页面或协作开关改变判定。

校验使用合并后的有效字段，兼容进展服务上下文中传入的完成/阻塞信息。Hook 只保留协作策略、督办、消息等职责；核心进展事实与阻塞阶段的记录职责按第二批迁移到开关之外。延期审批等已启用策略继续执行。

历史兼容：已存在缺少说明的完成/阻塞记录允许原样读取，并允许不触及状态或成果/阻塞字段的无关修改；页面标注待补证。人工重报状态、编辑成果/阻塞字段或正式提交时应用新规则。`importSource` 不是永久豁免凭证。可信历史导入可保存原始缺证事实，审计标识导入来源，不自动生成新的完整性证明。

独立作废命令仍只应用原作废资格与原因规则，不要求先补完成说明；`cancellation` 不进入普通可编辑字段。

## LP-05 异步页面一致性

`src/App.tsx:63` 当前只保护账号切换；`src/pages/WorkFollowups.tsx:30` 直接写回读取结果。为每个资源增加以下保护，先做局部 helper，不引入全局状态库迁移：

- 身份/权限代际：切账号、退出登录或授权变化，失效当前所有结果和缓存。
- 请求序号：只有同代际最新请求可以写数据、错误和 loading；旧请求失败不得覆盖新成功状态。
- AbortController：取消旧 GET 以减少负担，序号保护仍保留。
- 写入屏障：保存成功时立即失效此前启动的 GET，应用当前身份下的响应对象，再启动新 GET。保存期间切换身份时，不把旧账号的写入响应放进新页面。
- 对象版本：同一授权范围中的同一对象只接收不低于现有版本的结果。完整新列表决定成员集合，不能把旧对象并入新快照，避免恢复已作废、删除或失权的对象。

完整读取在写入屏障后仍出现低版本时视为需重读的数据异常，保留已确认的新对象并标记待刷新，不用旧集合覆盖。未来分页时此规则仅作用于该查询范围，删除/失权通过明确的失效通知或重新授权查询处理。

`refresh()` 返回当前有效读取的完成承诺；被后续请求替代时转为等待后续读取，不能让 `finishSaved()` 提前宣称已刷新。仅在有效读取失败时沿用 `SavedResultError`，提示“已保存，刷新失败”，按钮只重试读取。组件卸载后不再 setState。
