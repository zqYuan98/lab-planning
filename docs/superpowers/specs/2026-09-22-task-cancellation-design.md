# 已删除周安排的旧任务作废

用户反馈一项周安排因缺少月度关联已删除，但部门任务总数与“草稿·待审 / 未排周”仍出现。只读核查确认：周记录有删除标记，原任务仍为进行中且保留进展。现有模型只删除周安排，不代表整项任务失效；前端拿不到删除记录，将保留的任务归入未排周。

用户已明确选择“旧任务已不用：作废后退出任务总数和待办统计，保留历史”。据此采用管理员显式作废，不根据删除周安排推断任务是否继续，也不将作废伪装成完成。

## 行为

- Task 新增独立 `cancellation` 信息，记录时间、操作管理员和必填原因；原状态、月度关联、进展及审计保留。
- `POST /api/tasks/:id/cancel` 接受当前版本和原因。只允许管理员，已作废或版本不符返回冲突；任何未删除周记录（含草稿、历史周）仍存在时阻止作废，避免改变这些有效记录的统计。
- 周安排删除结果保留补关联、重建入口，并提供作废原任务。部门概览中没有任何有效周安排的任务详情也提供入口，解决已删除后离开页面的旧任务。
- 作废后默认 bootstrap 不再返回该任务，概览、工作清单、搜索、催办和原生待办不再把它当作待处理工作；备份和历史快照保留完整对象。前端读模型也防止含作废标记的宽范围数据重新计数。
- 作废任务不能继续更新、补关联、建立周记录、接收新催办或通过导入重新安排。任务级待处理催办、阻塞和督办关闭，历史回应、进展保留。
- 不自动批量作废其他任务；没有恢复入口，后续新工作应另建任务。历史提报和已保存报告不改写。

## 验证

覆盖权限、必填原因、版本冲突、其他周/草稿阻止、审计事务回滚、原任务进展不变、各统计退出、保留任务仍可重建、导入/备份/映射、通知和待办失效，以及桌面/移动确认交互。发布前验证正式版本基线与封存包，备份数据库；生产只对用户确认的这一条旧任务执行审计作废，不改其他业务数据。
