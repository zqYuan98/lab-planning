# 我的工作清单与领导交办

## 已确认需求

用户已于 2026-09-20 确认：本人记录，汇报时展示或导出；首期实现快速记录、领导交办筛选、排入周计划、汇报预览与导出。既有设计审批已完成，按此范围实现，不重复请求确认。

## 业务行为

- 新增常驻导航「我的工作清单」，管理者和成员均默认且仅展示自己的任务。全部在手是默认视图，不随周/月翻页丢弃未完成任务；另有领导交办、待安排、本周推进、待反馈、已完成视图与关键词搜索。
- 快速记录支持一行一件事，录入前显示拆分清单；1–50 条，每条标题最多 300 字。只要求事项标题，来源默认领导交办；交办人、交办日期、预期交付与截止日期可补充。未知日期留空，显示「待确认」。相同内容网络重试幂等，批量写入全部成功或全部回滚。
- 沿用 Task，不建立第二套任务。新增可选元数据：workSource (leader/self/coordination)、assignedBy、assignedOn、requestedOutcome、priority (high/medium/low)、estimatedEffort、currentProgress、decisionNeeded、waitingForFeedback。来源与既有 workOrigin 录入身份分别保存；后续关联月目标仍保留来源。
- 快速记录建立独立临时任务，临时原因记录来源背景；已有正式月目标任务也可补充领导交办来源。新老任务均可在清单编辑交付、截止日期、优先级、预计剩余投入、当前进展、下一步、所需决策。预计投入为自由文本，不从条数推算工时。
- Task 总体状态继续采用 todo/doing/blocked/done，待反馈为独立标记；完成时清除待反馈标记，完成须填写完成说明，受阻须填写原因。周完成不能自动关闭总体任务。清单保存遵守既有版本冲突、本人权限和督办对截止调整的校验。
- 待安排：未完成且当前周及未来周均无周记录；本周推进：未完成且本周有周记录（含草稿，明确标签）；已完成单独查看，其余视图不含已完成项。优先级在前，再按已知截止日期、创建时间稳定排序；未注明日期不会误判逾期。
- 「安排本周」进入已有周任务表单，携带原 taskId 和 ownerId；已有本周记录时进入更新入口。保持同一 taskId、每周唯一。清单录入不自动提交周报，跨月关联继续走现有月目标流程。

## 汇报

- 「汇报预览」对当前筛选结果生成内存快照，标明本人、生成时间、筛选范围、事项数、截止待确认数和需要协调数。未知截止、未排期和待反馈都保留。
- 明细含事项、来源/交办人/日期、预期交付、总体状态、当前进展、下一步、截止、优先级、预计剩余投入、需领导决策。周进展可作为缺少手填当前进展时的参考，标明对应周；不以周状态覆盖总体状态。
- 导出 Excel 可打开的 UTF-8 BOM CSV，正确转义换行/引号/逗号并防公式执行；导出使用预览快照，预览打开后后台变化不悄悄改变导出内容。浏览器打印只打印此预览。数据未发送外部平台，不增加领导账号依赖或公开链接。

## 集成与兼容

- 空日期按显式空字符串存储；正常周/月表单的日期要求保持现有界面行为，新增快速录入与任务编辑允许截止待确认。
- 新字段可选，老任务缺字段显示未注明，不能推断全部 self 来源为领导交办。业务 JSON 迁移、Excel/CSV 业务导出保留新增字段；SQLite JSON 存储不需破坏性迁移。
- 新增快速录入请求收据用于防重，与 Task 写入同一事务，不产生下发通知，不更改来源审计含义。数据恢复后沿用现有任务恢复与请求重放语义；收据不算业务任务。
- 权限沿用本人/管理者：后端新增接口仅给当前用户创建任务，不能通过传 ownerId/creationKind 给别人下发。现有更新权限不放宽。
