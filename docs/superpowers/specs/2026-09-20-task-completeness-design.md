# 工作事项完整性修复设计

用户已确认审查报告并明确要求修改、正式部署。本设计落实 `docs/task-completeness-audit-2026-09-20.md` 的修复顺序，不重复申请同一授权。

1. 所有已正式发布的月目标统一显示“已发布”；来源用独立标签。本人和本人参与目标可建立个人任务，管理者本人也有入口。
2. 导入逐项展示已写入、已有、未选择、待处理；未选择必须有排除理由，保存审计选择前后值。新 AI 候选一律选中，不能接收模型控制选择/系统关联/总体完成等字段。历史批次只读展示未导入项，不擅自重建任务。
3. 上传文件默认选择全部工作表，保存解析选项；重新识别显式重调模型。需要文件原文核对确认才能提交文件导入，记录核对人、时间、原始事项数，数量须与最终实际事项数相符；未选真实工作仍计数，有理由的重复/非任务候选可剔除，编辑/重识别会使确认失效。表格提供逐源行覆盖提示；图片/文本可预览原资料，支持人工补录漏项。该机制依赖用户核对，不宣称 AI 能数学证明原文语义完整。
4. 导入保留明确选择的交办来源和协作人；模糊姓名/项目映射提示核对。总体完成使用独立 `taskCompleted` 确认，周完成不自动结束任务。拒绝模型截断的响应。保持历史缺字段兼容、通知导入静默、幂等与事务回滚。
5. 工作清单汇集本人 Task 和本人负责、未验收、未拆本人任务的月目标，目标作为明确“待建立个人任务”的只读事项，不伪造 Task，不复制他人责任。目标也纳入在手/待安排及报告，建立真实任务后按目标关联去重。草稿/待审核目标显示其真实状态，未发布不能正式排周。
6. 领导交办以明确 workSource 为准，缺失时兼容可靠 assigned 来源；不猜测所有临时导入。来源不明可筛选核对。旧导入 done 但无整体完成说明的事项另显“整体完成待核对”，保留原库状态并可通过正常编辑确认。
7. 无数据库全量重写。生产部署保留账号、原数据、会话、通知及环境配置；部署锁、备份锁、短暂维护、停止后备份、哈希和实体核对、代码回退。禁止用旧库覆盖上线后的数据。

验证：导入服务器/API/界面与清单报告端到端测试；历史三行原图只读副本应显示 3 候选、2 导入、1 未导入；未拆目标、旧 assigned、新 assigned、周完成继续推进、协作人、漏项补录与重新解析均覆盖。桌面/手机浏览器验收；封存发布包完整测试、构建；线上只读数据投影和公网资源核验。
