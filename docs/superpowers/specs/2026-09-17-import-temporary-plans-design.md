# 导入临时事项到月度与周计划

## 需求与选择

导入校对目前只有月度、每周内容类型，临时属性在解析、校对和写入阶段均缺失。用户需要把领导临时交办等工作加入月度或周度计划。

采用独立的任务性质属性：kind 继续表示 monthly / weekly，新增可选 isTemporary 和 temporaryReason。临时性质不作为第三种周期，也不通过“没有项目或月目标关联”推断。

## 用户流程

- 校对时明确选择“纳入计划”：月度计划或每周计划；另选“任务性质”：常规工作或临时交办。
- 临时事项显示“临时原因 / 交办说明”。校对阶段允许暂存缺项，加入计划时必须填写；原因不自动编造。
- 所选类型突出对应月份或周次；临时周任务可以不关联月度目标。若关联已有任务，性质和原因沿用已有任务，不能在导入时改变原任务。
- 提供勾选记录的批量性质/说明设置，预览和历史中显示临时标记。
- 生成新计划草稿：成员可以创建本人临时月目标及临时周任务；普通月目标仍由管理者维护。后续提报、审核、发布沿用既有流程。
- 导入已有计划：管理员核对后生效；成员仍须交管理员确认。月度验收与每周整份提报不被临时标记绕过。
- 仅存历史资料：保存临时属性及来源，允许原资料存在缺项。

## 业务与兼容

- 临时月目标映射 MonthlyPlan.isTemporary / temporaryReason；临时周任务映射 Task 同名字段。
- 临时周新任务不能同时挂系统月目标或本批次月目标。已发布临时月目标下新建的周任务仍按目标内普通任务管理。
- 普通已有周计划允许没有月目标关联的既有规则不变。
- AI 仅在原文明确临时时提取 true 与原文说明，不根据领导姓名或缺关联猜测临时性质。原始文件、文字、权限及系统 ID 匹配规则不变。
- 新字段可选，旧数据按普通处理；普通行的去重指纹保持原字节算法，临时行才追加属性，防止旧批次重导冲突或重复创建。
- 草稿转生效沿用原 ID。原记录不因重复导入被重新分类或覆盖。
- JSON 迁移、历史和审计快照保留新字段，旧格式无字段仍能读取，不修改数据库存储版本。

## 验证与发布

测试覆盖两种周期与三种保存方式、成员/管理者权限、临时原因缺项、月周关联冲突、引用已有任务、草稿激活与旧指纹兼容、业务导出/恢复。浏览器使用合成记录完整校对、批量设置、保存和落入对应计划，不修改正式资料。发布前构建、回归与隔离容器验证；线上沿用现有数据卷并备份，正常并发写入只做差异审计。
