# 管理员下发周计划

用户已确认：管理员安排给成员的周计划进入该责任人的“我的周计划”，明确区分管理员下发、成员自建、管理员代录；归属按责任人，填写人留痕。成员更新进展并在周五核对整份提报，下发不自动生成成员提交回执。日计划不加入。

## 方案

沿用 Task → WeeklyRecord → WeeklySubmission，不复制一份“下发任务”。仅从日志计算标签无法稳定保留新代录意图；单独建下发表会增加同步风险。因此在任务和周记录上保存可选 workOrigin `{kind: self|assigned|proxy, actorId, reason}`。时间沿用记录 createdAt。每周来源独立，成员续排下发任务时新周为成员自建；原任务来源保留。服务器确定 actorId，成员只能 self；管理员给别人默认 assigned，proxy 必须填写原因。来源一经创建不可由更新接口修改。正式整份代提交继续使用原有必填原因及 actorId 留痕。

管理员创建界面必须明确选择责任人；可选择“下发任务”或“代成员录入”。选中责任人后只列出其可关联月目标及个人任务。下发保存即进入成员列表，草稿/纳入周统计与来源分别显示，不自动形成周五回执。成员填写人自己的记录时无需重复录入管理员下发项。

旧记录采用只读投影：无 workOrigin 且非导入记录时，查找本实体初始创建事件（before 为 null，after 的 id/ownerId 匹配）。创建人等于责任人标自建，不同且创建动作是 create/submit 标管理员下发；其他情况来源未记录。不从最后修改人推断，不覆盖导入来源，不自动改责任人，不改历史回执。投影不写数据库。导入/导出 schema、用户引用及重映射支持新的来源字段。

## 验收

管理员下发后仅责任成员可见并可更新；另一个成员不可见/不可修改。成员本人整份提交前仍待整份提交，提交后回执归属成员，任务来源仍为管理员下发。代录需要原因且与整份代提交分开。管理员为自己创建为自建。旧数据投影不更改实体版本/数量/内容；已有导入记录不误判下发。导出恢复与用户重映射保留来源。浏览器检查责任人选择、来源提示、成员可见及完整提报跳转。部署前备份，保留上个版本回滚能力。
