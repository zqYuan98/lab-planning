# 审批、发布权限与导入操作审查修复

用户要求审查全系统审批及发布权限，修复管理员无法找到月度目标发布入口、导入校对操作不清楚等问题。本次实施依据该修复授权；不会替用户提交、审批或发布任何真实业务记录。

## 已确认问题与处理原则

1. 月目标后端已有 `draft/returned → submitted → approved → published` 流程，管理员可提交、审核和发布。工作清单却一律引导建立任务，详情缺少状态对应的动作；这属于入口缺失，保留业务审批规则并贯通入口。
2. 月目标审核通过后退出待审核队列，却没有待发布队列。补充“月目标待发布”，点击进入具体目标的发布确认，区分单项目发布与全月批量发布。
3. 受托目标负责人拥有整份周计划审核权，但待办只给管理员。复用整份计划的实时权限和有效提交判断，生成成员最小待办并导航到专用审核队列；不扩大私有周记录读取权限。
4. 发布接口仅接收 ID，无法确认实际发布内容与用户看到的版本一致。请求必须带完整 `planVersions`，事务内先校验全部版本、状态、月份和项目有效性，再执行发布与快照，失败不部分发布。
5. 钉钉导入把未选中的待处理重复项算成“已排除”。只有明确排除决策才计入已确认排除，待处理单列。
6. 导入页校对、完整性确认和导入分散，部分禁用按钮无解释。统一阻断原因与主动作条件，提供步骤与定位入口；校对操作在完整性确认之前。按钮沿用工作台风格，扩大可点击区域，显示准确对象与条数。

## 角色与状态边界

- 管理员：按现有规则处理全部门月目标、周审批、延期及成果；管理员自建月目标仍需显式提交、审核、发布。
- 普通成员：仅执行本人被允许的提交或成果操作；整份周计划受托审核由当前委托、目标归属及完整快照实时决定。
- 观察者、停用或未获准账号：不因前端入口调整获得写权限。后台始终校验实时身份。
- 历史/已合并目标、归档项目以及权限撤销：界面说明限制，服务端继续拒绝越权或无效状态。
- 导入确认只生成草稿；导入、审核、发布和成果验收是不同动作。现有计划直接生效模式的既有语义保持。

## 实施与验收

按后端权限与发布事务、月目标入口、待办与周委托入口、导入可用性四个范围并行实施。复用现有服务，避免为提示另造权限规则。

测试覆盖管理员/成员/观察者及身份降级、月目标各状态入口、单项与整月发布范围、过期版本和混批回滚、委托授予/撤销/转移/提交变化、重复项统计、全部导入阻断原因。运行完整测试、类型检查与生产构建，并在隔离数据中验证桌面与窄屏流程。真实系统仅只读复核，不以自动测试替用户批准业务数据。

后续验收记录需区分已检查无问题的范围与具体修复项，不宣称穷尽全部可能缺陷。
