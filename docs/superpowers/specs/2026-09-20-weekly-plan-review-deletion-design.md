# 周计划审核与管理员留痕删除

用户于 2026-09-20 已确认实施：管理员删除单条周安排；成员整份提交下周计划，由管理员通过或退回，退回后修改重提。此前两轮评估及用户“好的加上”构成设计和实施授权，不再重复请求许可。现有工作区包含其他功能，保留全部已有修改；本轮不自动部署或操作生产数据。

## 流程与边界

复用 Task → WeeklyRecord → WeeklySubmission。新增审核绑定每人每周 `kind=plan` 的具体不可变提交版本。状态为未提交、待审核、通过、退回、内容变化待重提、历史无需审核；退回必填意见。管理员审核内容包括成员、所属周、每项承诺、月目标关联及提交时任务上下文。

首次准时/迟交、截止缺交事实仅按原正式提交回执计算；审核不调用回执 invalidate。修改成果、证据、阻塞、执行状态不撤销计划批准；增删条目、修改承诺、任务/责任/所属周/月归属则必须重审。提交防并发仍校验完整 id/version manifest；审核另比对计划内容，防止旧页面批准已改计划。返回的审核视图独立于本周完成情况的 changedSinceSubmission。

批准后计划内容改动，当前改动条目暂不计入已审核正式计划；旧批准版本保留在历史中供查看。未改条目的既有批准仍有效。审核不把未经批准的新内容套用旧结论。实际进展允许如实保存，界面明确显示待审计划和已有执行反馈。

管理员正式下发的安排属于已确认来源，成员整份提报中仍展示；下发草稿和代录不自动等于批准。成员修改正式下发安排的承诺后，适用周期仍需重新审核。月目标既有发布、参与人员、月份相交及临时工作原因校验继续生效，周审核不代替月目标审批。

## 数据契约

- `WeeklyRecord.deletion?: {deletedAt, deletedBy, reason}` 保存删除事实；原行仍存在。
- `WeeklyRecord.planApproval?: {required:true, approvedSubmissionId:string|null, approvedFingerprint:string|null, suspended?:true}` 保存生效依据与按周期暂停的免审标记，历史缺省兼容。
- `shared/weekly-record-state.ts` 集中定义 `isActiveWeeklyRecord`、`weeklyPlanFingerprint`、`isEffectiveWeeklyRecord`。指纹仅含计划字段，不含 version、进展或审核元数据。
- `weeklyPlanReviews` 保存审核人、时间、结果、意见、submissionId/dutyId/ownerId/所属周期及 requestId，通过 submissionId 引用不可变计划指纹清单，属于业务迁移包。每份提交最多一个审核结论。
- `WeeklySubmission` 可保存 `planManifest`，以及任务标题、截止日期、说明和月目标标题、月份的冻结上下文。老提交不补造这些字段。
- 规则持久保存新审批生效周：默认下一完整提报周期的下周内容；重启不顺延，历史不补造批准。审批服务及写入门禁使用同一规则；新适用的自报/代录记录须审核，已有历史仍可读取。
- 审核 API 要求 manager、指定 submissionId、预览时 duty version 和决策；事务内重新核对最新有效提交及计划内容。重复/过时决策须幂等或明确 409。

审批适用性同时取决于 `planReviewEffectiveWeek` 和提报规则窗口。暂停与恢复从下一完整提报周期生效；同步受影响未来条目的 `suspended` 标记，保留原批准依据。暂停周期正式保存的计划按免审口径生效，新开放周期恢复审核要求；已经结束的暂停周期不补审。规则重启不顺延，历史快照不回写。作废已批准回执时清除当前引用它的批准；恢复回执仅在当前条目未改、未删、仍正式保存且无其他批准时恢复原批准。

## 删除

管理员 DELETE `/api/weekly-records/:id` 提交 `{version,reason}`，只删除指定周安排。原 Task、任务完成状态、月目标、其他周记录、周提交/报告快照和历史进展均保留。删除审计记录操作者、原因及前后状态。原行不可编辑/承接；同 Task + 周唯一性仅计算未删除行，允许沿用任务重建。首版不增加恢复入口，避免重建后的冲突。

相关待处理催办/阻塞支持及待确认义务失效，历史回应不清除；整个任务的其他催办不受影响。新列表/统计/报表不包含删除行，历史快照照常读取。待审提交含删除行时必须重新提交；已批准的旧提交只作为历史。删除不抹去迟交或缺交。

界面提供管理员删除按钮、确认弹窗，展示成员、所属周、承诺及历史保留说明，原因必填；成功后可沿用原任务重新安排本周。

## 兼容与验证

正式统计、报表、部门概览和相关通知/督办统一调用有效性规则；日常成员列表保留未删待审行供修改。导出必须保留删除墓碑及审核集合、引用和用户映射，恢复只对未删除行校验 Task+周唯一性，旧迁移包继续兼容。已有报告不可回写。

恢复预览与确认使用同一规范化过程：旧包缺少审批元数据时，将当前规则适用的成员自报、代录和下发草稿标为待审核；正式已下发安排、已删除行及嵌套历史保持原语义。旧包规则缺少审批边界时继承目标已持久保存的边界，并显示说明。当前批准不得引用已作废的回执，历史快照可保留原批准；当前暂停标记必须与规则窗口一致。恢复不产生新通知或外发投递。

验证权限、删除版本冲突/事务、同周重建、历史快照及任务保留、审核通过退回重提、并发编辑/旧版本审批、进展不重审、按时记录不受审核延迟影响、下发/代录差异、临时/月度门禁、导出恢复、新周期边界及单条写入绕过。运行相关测试、全套测试和生产构建；使用隔离合成数据验证浏览器流程，不触及真实业务库。
