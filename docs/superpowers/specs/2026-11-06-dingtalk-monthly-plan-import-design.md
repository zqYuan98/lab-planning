# 钉钉月度目标获取与导入设计

日期：2026-11-06（Asia/Taipei）

状态：用户已批准实施，开发与本地验收已完成，生产只读连接已验证；尚未部署上线。实现范围与验收证据见[验收记录](../../validation-2026-11-06-dingtalk-monthly-import.md)。

## 1. 需求与本期决策

管理者每月新建一份钉钉月报材料，其中包含下一月份的目标。系统按所选目标月份找到相应材料与目标工作表，管理者点击获取，预览并校对后导入，免去复制文字、截图和上传识别。

用户已确认交互为“点击获取并预览，确认后导入”，并补充“每个月都会新建一个月报材料，然后去找到本月目标即可”。因此固定的是文件夹及查找规则，每个月分别发现并绑定实际文件、Sheet，不永久绑定《10月月报材料》。

首期只面向管理者，入口在“数据导入 → 从钉钉获取”。采用草稿导入，后续沿用月度目标审核发布流程。获取、保存预览、导入草稿均不发布目标、不发送钉钉消息。原上传与粘贴入口继续可用。

## 3. 方案比较

| 方案 | 优点 | 代价及适用范围 |
| --- | --- | --- |
| 系统服务端只读连接，按月查找，点击获取并预览（推荐） | 在现有系统内完成日常操作；复用校对、权限和导入留痕 | 需为生产环境单独验证文档权限和读取能力 |
| 本机 DWS 读取后由桥接服务送入系统 | 可复用已验证的读取路径 | 依赖本机进程和登录状态；不能视为线上已具备自动获取能力，仅作为有明确运维归属的过渡选项 |
| 每月定时拉取待审阅批次 | 减少主动查找操作 | 多出调度、过期材料和通知处理；用户已选择主动获取，首期不做 |

推荐服务端连接方案。开发第一阶段先验证生产身份能否读取指定文件，再验证文件夹发现。若服务端官方能力无法覆盖指定文件夹发现，应明确报告该能力缺口；经用户选择采用粘贴当月文件链接作为过渡，不把手动选链接宣称为完整自动发现。

## 4. 每月发现规则

1. 目标月份是完整 `YYYY-MM`，默认按配置时区取当前月，也可选择历史月或下月。以它作为业务归属，不能直接采用文件名的月份。
2. 固定连接及已绑定文件夹，限定在该文件夹及授权子目录内查找在线电子表格。通过文档标题与真实节点身份解析候选；若先全局搜索标题，必须另行验证文件夹归属。
3. 推荐候选标题为目标月的上一个月“月报材料”，例如 `2026-11 → 10月月报材料`、`2026-12 → 11月月报材料`、`2027-01 → 2026年12月月报材料`。实际标题不带年份时保留原标题，不能编造标题。
4. 文件名仅用于缩小和排序候选，最终列出工作表，按完整名称匹配 `11月目标`、`12月目标`、`1月目标`。完成情况、总结 Sheet 不匹配。命名变化时允许人工选择文件与 Sheet，并明显展示月份冲突，不做静默替换。
5. 候选卡展示完整路径、业务标题、目标 Sheet、文件时间、推定月份依据及已导入状态。只有唯一且无月份冲突的候选可预选；多个候选、历史同名文件或年份依据不足时由管理者选择，不能按“最近修改”直接认定。
6. 获取后检查表中明确年月。与目标周期冲突的行必须校正、排除并注明原因，或重新选择周期，不能直接改写源日期。源表没有年份时由目标周期补充，但在预览注明“年份来自所选月份”，必须确认。
7. 发现结果在确认获取后按月份保存绑定。同一月份再次进入可复用该绑定；换月重新发现，不能沿用上月文件 ID。旧文件失效时提示重新选择，保留历史来源记录。
8. 发现过程限制最多 3 层子目录、500 个节点、100 个候选工作簿；达到上限或有分页失败则显示“查找未完成”，允许进一步缩小范围，不能宣称唯一命中。上限作为部署可配置项。

## 5. 用户流程

`选择月份 → 查找月度目标 → 核对来源 → 获取并预览 → 校对与差异确认 → 导入月度目标草稿 → 按既有流程发布`

### 来源区域

- 目标月份：2026 年 11 月。
- 来源文件夹：人工智能实验室管理。
- 推荐来源：10月月报材料 / 11月目标。
- 操作：“查找月度目标”“更换来源”“获取并预览”。
- 初次绑定文件夹之后，日常无需重新配置文件夹；查找仅获取目录与 Sheet 元数据，点击“获取并预览”才读取目标内容。

### 预览与校对

- 顶部显示来源链接、目标月份、获取时间及原始行数。本次样本应为七条候选，不能把单元格里的多行工作内容自动拆成多个目标。
- 复用原文对照工作台，显示事项、完整工作内容、交付与验收要求、负责人、截止日期、备注以及匹配的系统成员和项目/工作类别。
- 可编辑候选、匹配负责人、选择项目或保留类别、排除并填写原因。保留源行原文，编辑不反写钉钉。
- 显示新增、已导入、待处理变更、未匹配、已排除数量；只有所选记录通过校验和完整性核对后才能提交。
- 主要按钮为“保存校对”和“确认导入 N 条草稿”；成功后提供“查看本月目标”。草稿仍需审核发布。已有导入页的默认 `existing` 模式不能自动继承到此入口。

## 6. 字段映射

| 钉钉列 | 系统字段或处理 |
| --- | --- |
| 序号 | 原始事项编号及对账依据，不能单独视为永久 ID |
| 部门 | 核对所属部门并保留来源，不自动创建部门 |
| 指标类型 | 默认映射工作类别 `category`；如“部门重点任务”，不推断优先级 |
| 工作事项 | 目标标题 `title`；不凭标题自动创建项目 |
| 工作内容（做什么） | 完整映射 `expectedOutcome`，保留换行和条目编号 |
| 交付产物（可量化验收标准） | 原文映射 `acceptanceCriteria`，不生成额外量化指标 |
| 负责人 | 原始姓名保留；唯一有效姓名匹配系统成员，同名、缺失或停用时人工选择 |
| 截至时间 | 转为日期 `YYYY-MM-DD`；兼容“截止时间”表头，保留原始单元格值；不擅自补月末 |
| 备注 | 保留独立来源列；首期在 `expectedOutcome` 后加“补充说明（原表备注）”原文，避免进入目标后信息丢失；不自动标为阻塞 |

所属月份取所选完整年月；负责人以外的参与人员不推断。该目标 Sheet 的 `actualOutcome` 为空、成果验收待确认，不能把计划内容理解为已完成。

当前样本有完整工作类别、工作内容和验收要求，可满足草稿导入所需字段。后续缺少草稿必填字段时显示待补充并阻止该项提交，预览可保存；不为通过校验编造内容，也不静默改成直接发布模式。

首期以表头模板做确定性映射，不依赖 AI 配置。表头缺失、重复或结构变化时让用户修正列对应关系；复杂合并区域不按空白盲目补值。普通空行和表头排除必须有可核对依据。AI 解析继续作为原导入流程的显式选项，本功能不自动向模型发送表格。

## 7. 快照、差异与重复处理

### 来源身份

- 团队范围来源身份：`connectionId + folderId + documentId + sheetId + targetMonth`，与获取操作者分离。
- 获取快照：业务标题、路径、源 URL、原始单元格、实际读取范围、行列与合并信息、读取时间、可用的远端版本，以及规范化内容摘要。
- 快照版本与来源身份分别保存，不能用每次抓取时间生成新的来源身份，也不能把每次内容变化当成全新无关文件。
- 所有有效行必须完整读取。范围分段、分页或截断异常时只保留失败进度，不能生成可导入的“完整”批次。

### 行级决策

- 相同内容重新获取，恢复原批次与已保存校对；不同管理者获取同一来源也不重复建目标。
- 完全相同的已导入源事项显示“已导入”。行号只作原文定位，不用作稳定业务身份。匹配组合包括原始序号、原文内容摘要和既有人工关联；有歧义即待核对。
- 内容变化显示旧值、新值和关联的系统目标。首期只允许导入明确新增项，已导入项的修改在原目标页面人工处理，不自动更新、删除或撤销已有目标。
- 插行、排序、改序号、改标题、拆分合并出现多个可能匹配时，必须手工关联原事项或确认确为新事项。源表删除行只提示“来源已移除”。
- 同月份更换文档、通过旧截图入口已导入、或新建材料复制了旧内容时，对比该月份系统已有目标；标题和负责人相似只能作为疑似重复提示，不能自动合并。存在疑似重复的选中项须逐条确认“关联已有 / 确认为新 / 排除”。
- 首次人工关联结果持久保存，便于再次获取对账。不能修改源表来插入系统 ID。

### 确认时一致性

提交携带批次版本、预览快照摘要与完整性核对结果。提交前重新核对源表内容或可靠版本；源表内容变化时提示重新获取并核对差异，读取失败时保留预览但不提交，不能悄然导入另一版。

实际写入使用已确认的冻结快照。远端核对与本地提交不构成跨系统原子事务，界面和审计需注明快照时间；核对之后发生的远端变更在下次获取时处理。人工校对与源表原文分别保留。

本地写入以事务执行，连同来源项关联、去重事实一起提交。双击、请求重试和两名管理者并发确认只能产生同一结果；目标版本变化或新增重复时返回冲突并要求重新预览。删除导入批次后继续保留必要去重事实。

## 8. 系统改动边界

| 模块 | 职责 |
| --- | --- |
| 独立钉钉文档连接器 | 验证连接、限定文件夹发现、解析业务标题与节点、列 Sheet、完整读取目标范围；不写业务目标 |
| 月度来源服务 | 目标月份选择、候选与按月绑定、来源快照、差异及来源项关联 |
| ImportService 适配入口 | 从可信服务端快照建立待校对批次，默认 `mode: draft`，显式 `requiresCompletionReview: true` |
| 现有校对与提交 | 复用成员匹配、原文核对、排除理由、完整性校验、批次版本检查和事务创建目标 |
| 独立前端来源组件 | 放入 Imports 页，承担查找、候选选择和获取状态；避免继续把连接逻辑堆进大型页面 |

参考现有文件：`server/import-routes.ts`、`server/import-service.ts`、`server/import-files.ts`、`shared/import-types.ts`、`shared/types.ts`、`src/pages/Imports.tsx`、`src/components/ImportSourceReview.tsx`、`server/dingtalk.ts`。

不要直接把结果送进现有 `/imports/structured` 就视为完成：该接口默认不强制完整性核对，只保存提交 JSON，而钉钉入口必须保留实际单元格与完整来源覆盖证据。连接器返回内部标准结果，避免把 DWS 输出字段与业务服务耦合。

连接凭据只由服务端管理，不进入浏览器、日志或业务导出；使用受限的文档读取权限。管理员功能权限、连接所属组织和资源权限分别校验。生产连接方式须在技术验证后锁定，不能复制本机登录状态作为默认部署方案。

官方接入依据：

- [阿里云 DataWorks 的钉钉表格权限说明](https://help.aliyun.com/zh/dataworks/user-guide/data-analysis-sql-query-results-spreadsheet-generation-dingtalk-fly-book-wechat-form/)列出 `Document.Workbook.Read` 对应工作表与单元格区域读取；目录权限须另外核对。本功能只取需要的读权限，不照抄其导出场景的写权限。
- [阿里云 PolarDB 的钉钉文档同步说明](https://help.aliyun.com/zh/polardb/polardb-for-postgresql/sync-dingtalk-documents-to-the-knowledge-base)区分接口权限、应用可使用范围和操作用户资源权限；拿到应用令牌不等于可读目标资源。
- [阿里云发布的钉钉 SDK 接口声明](https://pkg.go.dev/github.com/alibabacloud-go/dingtalk/v2@v2.0.83/doc_1_0#GetRangeRequest)提供工作表、范围读取及操作身份参数。连接器应分别保存已验证的文档节点与工作簿标识，不能把本机 DWS 的 `nodeId` 直接假定为生产 OpenAPI 的 `workbookId`。

以上支持服务端读取方案的可行方向，不替代对本企业、实际文件夹和操作身份的连通验证。

## 9. 异常表现

| 情况 | 用户看到的处理 |
| --- | --- |
| 未找到文件或目标 Sheet | 显示查找范围和月份，允许重试或更换来源；不退到完成情况 Sheet |
| 多个候选或年份不明 | 展示候选与依据，人工确认 |
| 文档权限不足或授权失效 | 显示重新连接/授权入口，保留校对内容 |
| 超时、限流或部分读取 | 标记获取未完成，按可重试语义重试，不导入部分表格 |
| 人员、日期或必填字段有问题 | 定位源行，待校正；允许先保存校对 |
| 源表或系统记录发生变化 | 展示差异，重新核对，保留原快照与用户已编辑内容 |
| 同月已导入 | 打开既有批次或目标，展示新增及变化，不重复建计划 |

## 10. 实施顺序与验收

1. **连接验证**：用生产部署将采用的身份，只读获取本次已核实工作簿和目标 Sheet；再验证指定文件夹范围内发现及业务标题解析。确认可长期运维的授权方式。失败时先处理权限或能力缺口，不承诺已接通。
2. **最小闭环**：按月查找、来源确认、全量读取、固定列映射、原文预览、人工校对、完整性确认、事务导入草稿、查看目标。包含来源身份与重复拦截。
3. **差异与验收**：重复获取、源表变化、同月换文件、旧入口重复、跨年、缺 Sheet、同名资料、部分读取、权限失效及并发提交。补充文档、针对性服务测试和桌面/手机流程验证。

关键验收结果：

- 2026 年 11 月能发现《10月月报材料》的“11月目标”，七行生成七个候选，九列信息完整保留；“10月目标完成情况”不混入。
- 选择 12 月后重新发现新月报材料；选择 2027 年 1 月能正确处理上一年 12 月文件，历史同名材料不能被静默选中。
- 仅查找或预览时，系统月度目标数量不变；确认后只新增所选有效草稿，未发布、未外发。
- 同一来源重复确认、另一管理者接手和网络重试均不重复创建；排序与插行不误关联原目标。
- 原表修改不会覆盖已有进展，原表删行不会删除系统目标；有异常的范围不以完整成功提交。
- 本次草稿导入的自动化测试验证无发布快照及外发投递；后续人工发布继续沿用既有行为。
