# R2 资源交付与最小使用率运维说明

本说明对应 R2 的本地实现。此次工作没有在真实环境开启使用率采集，也没有完成目标 Linux / 容器发布、真实使用率观察或发布后连续运行验收；这些状态应以交付验收记录为准。

## 构建与 HTTP 交付

`npm run build` 同时产生前端编译版本、`dist/build-info.json` 和 Vite 构建清单。可在构建时指定符合格式要求的 `APP_BUILD_VERSION`；未指定时生成带时间的版本。服务启动读取实际 `dist/build-info.json`，因此应将整套 `dist` 作为同一构建发布。正式环境缺失或损坏版本信息会提示重新构建，不应靠手工修改版本文件掩盖构建不一致。

- 仅 Vite 清单中带内容哈希的构建资源返回 `Cache-Control: public, max-age=31536000, immutable`。
- HTML、构建版本文件及其他可变静态文件使用 `no-cache`，允许浏览器用条件请求重新验证。API 保持 `no-store`。
- 缺失的静态资源返回真实 404；不会用 HTML 页面代替不存在的 JavaScript、CSS 或图片。合法页面导航仍可回退到应用入口。
- Node 按 `Accept-Encoding` 协商压缩并维护 `Vary: Accept-Encoding`，跳过不适合压缩的类型、分段响应及事件流。Nginx 示例关闭重复压缩和代理缓存，并透传编码协商、缓存及验证响应头。

主要页面和报告重组件按需加载。普通渲染错误可局部重新打开；浏览器缓存的动态模块下载失败和 CSS 预加载失败使用“刷新页面并重试”。刷新仍经过现有草稿和未保存报告保护；继续编辑会保留当前内容。模块加载恢复不会改变业务权限和深链含义。

## 使用率设置与数据范围

管理者在“钉钉通知设置”页面的“最小使用率统计”区域开启或暂停统计，选择排除的测试账号，并查看聚合。默认关闭、默认保留 90 天，也可选择 30 天。只有管理者能读取配置和聚合或修改设置；普通成员仅能查询自身采集是否启用并上报固定页面枚举。观察者、管理者、不可用账号和明确排除的测试账号不参与统计。排除账号时会移除其已经保存的统计。

统计覆盖以下固定范围，不接受任意事件名或事件负载：

| 类型 | 范围与计数方式 |
|---|---|
| 页面 | 工作概览、月度目标、周记录、年度目标、项目、导入、消息、协作、工作清单、反馈、授权工作、周期复盘。按北京时间日期、成员、版本、页面去重。 |
| 成功动作 | 保存任务、批量收件、保存周记录、正式周提报、保存或提交月度目标、记录进展、提交交付、提交反馈。批量收件按成功批次计一次。 |

动作由服务端固定业务路由的成功响应产生，使用持久业务实体版本或不可变成功对象 ID 建立去重指纹，不接受客户端宣称成功的动作。失败请求、读取、采集请求、集成运维接口和管理者操作不会成为成员动作。命令重试、URL 编码别名、页面刷新及跨发布重放不会重复增加同一个动作。

仅保存固定枚举、日期、发布版本、成员的本地 HMAC 标识及必要的操作去重标识；配置另保存排除账号、启用环境和精确启停时间。不会保存业务正文、用户输入、附件、网址参数、IP 或 User-Agent，不向外部统计平台发送数据。输出仅为聚合，不提供成员事件明细。采集请求采用独立客户端请求通道，不触发业务写入通知或工作空间刷新。

## 分母与观察期解释

“活跃成员”指所选区间和发布版本中，至少产生一次已列页面访问或成功动作、且当前仍符合统计条件的成员。各项使用率的分母为这些活跃成员；同时展示当前符合统计条件的成员总数，不能把未访问成员误认为已经使用过功能。

聚合分别显示“连续启用的日历跨度”和“有记录的日期数”。本版本最近连续启用跨度少于 28 个日历日，或活跃成员少于 5 人时，页面提示观察数据不足。正常工作周只有工作日发生访问，不会因为缺少周末访问而被要求积累 28 个活跃日期。暂停后再次开启或切换发布版本会重新计算连续观察跨度。

28 个日历日与样本人数只用于提示数据量，不证明已经覆盖四个正常业务周。节假日、系统离线、试点范围、不同职责和月度周期仍需人工评估；该功能不会据此判断或自动建议删除低频功能。

旧页面的编译版本必须与服务端发布版本一致才会采集页面，更新后仍停留在旧页面的成员需正常刷新页面。动作按实际成功时间判断：启用之前、同日暂停重开之前或新发布开始之前的旧回执不能回填到当前观察窗口；保留期外的旧回执也不能形成新的计数。

## 统计文件、留存与备份

生产统计文件为主库绝对路径追加 `.usage.sqlite`，与主库处于同一个数据目录。例如主库文件名为 `example.sqlite` 时，统计文件名为 `example.sqlite.usage.sqlite`。该文件使用独立 SQLite 连接；统计写入不会增加主库的工作空间修订号，也不进入业务实体集合。

保留期以北京时间日期计算，包含当天。启动、统计读写、设置变化和运行期间每小时的清理检查会移除超期事件；同一天的常规检查会避免重复清理 SQL。关闭采集仍保留自动清理，关闭不是清空全部历史。服务退出会先停止清理检查，再关闭统计连接。

业务 JSON 导出、业务迁移包和默认主库备份均不包含统计。统计文件不是业务恢复的必要条件；没有统计历史不会丢失业务任务、报告或权限数据。

如需单独保存统计，复用现有 SQLite 在线备份命令，将 `DATABASE_PATH` 指向统计文件并显式指定新的备份文件名。以下是示例占位路径，不对应真实环境：

```sh
DATABASE_PATH=./data/example.sqlite.usage.sqlite npm run backup -- ./data/backups/usage-YYYYMMDD.sqlite
```

备份命令以只读连接打开源库，使用 SQLite 在线备份并检查完整性，目标文件存在时拒绝覆盖。不要在运行期间仅复制可能含有未合并 WAL 的单个 `.sqlite` 文件作为备份。主库和统计备份需要分别执行，分别保管；本次没有执行真实备份或恢复。

## 恢复、克隆与故障

统计启用状态绑定主库的 operation epoch。业务恢复轮换该标识后，原启用状态自动失效，管理者页面会提示核对并重新开启。保存新环境的统计设置会清除旧环境的统计，开始新的观察期，不自动继承旧环境的启用状态。

完整数据库备份恢复或环境克隆仍应遵守既有恢复流程：停止对应应用，针对恢复后的主库运行 `npm run reset-operation-context -- <恢复后的主库路径>`，再启动并核对账号与设置。只替换文件而不轮换主库环境标识，无法让应用识别一次完整物理克隆。

统计文件损坏、无法打开或权限不足时，启动工厂保留原文件、输出不含业务内容的提示，并降级到强制关闭的内存实例，业务服务继续启动。该降级实例不能从界面重新开启，设置页会明确提示统计存储不可用。维护人员应检查原文件与目录权限、备份和完整性，修复后重启；应用不会自动删除或用空文件覆盖损坏的统计文件。

正常运行中一次统计写入失败不会撤销已经成功的业务响应；此类统计可能缺失，排查时应结合运行日志理解数据缺口。测试及未注入生产统计实例的开发应用默认使用内存统计库，不创建额外持久统计文件或后台清理定时器。
