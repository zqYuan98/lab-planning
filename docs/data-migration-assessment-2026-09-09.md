# 数据迁移、表格导入导出与智能填报：现状审查及建议

日期：2026-09-09。范围：当前 `lab-planning` 本地代码与部署记录。

本文记录已验证的能力、缺口和待确认的建设方案；不是功能已交付声明。未连接正式数据库，未导入真实表格，未变更服务器。工作区已有的账号注册相关修改保留原样。

## 结论

目前考虑了数据持久化、整库搬迁、备份恢复和部分业务历史保留，但尚未形成旧表格迁入、智能解析、业务数据导出及业务规则升级迁移的完整闭环。

目标应明确为：已经填写的事实能够持续复用；字段、流程和统计规则变化时，由系统转换和重新关联已有数据，只有原资料确实缺失或含义不明确的部分需要人补充。

## 建设路径比较

| 路径 | 优点 | 代价与适用性 |
| --- | --- | --- |
| 统一导入处理，先表格后直连（建议） | Excel、钉钉导出文件、未来智能体共用匹配、校验、去重和写入规则；先解决历史填报 | 首批需要建立导入暂存和批次管理；钉钉在线直连随后接入 |
| 只做固定模板导入导出 | 实现范围较小，适合格式已统一的数据 | 需要人工整理旧表，非标准历史表格仍有较多重复劳动 |
| 首批同时做钉钉直连和双向同步 | 能覆盖持续跨系统协作 | 需要确认表格类型、访问权限、冲突处理和哪边数据为准，首批范围明显增大 |

目前建议以 Excel／CSV、钉钉导出的表格及统一集成接口为首批范围；钉钉在线直连独立接入，双向自动同步另定规则。此优先顺序是建议，尚待用户确认。

## 建议的产品流程

上传原表或粘贴表格 → 识别工作表和表头 → 自动匹配字段与人员项目 → 展示解析预览 → 补充或确认少量疑点 → 批量生成填报草稿 → 沿用系统审核发布流程。

### 1. 保留原资料，支持重新解析

- 保存原文件、原始单元格值、工作表和行位置、导入时间及操作者。源日期与实际导入时间分开记录。
- 解析结果进入独立的导入暂存区，允许缺字段、关系不完整，刷新后仍可继续处理。
- 将字段映射、人员匹配和项目匹配保存为可复用模板。首次确认后，同类表格可直接套用。
- 规则修正或模型更换后，从保存的原资料重新生成预览；正式记录的更新必须先展示差异，保留已有人工作出的修正。

### 2. 智能识别与历史数据适配

- 程序先处理表头、合并单元格、日期和状态格式；模型用于不规则表头、多行工作描述、项目归类和候选关联建议。首批支持边界需用实际样表验收。
- 例如旧表的“姓名／工作内容／计划时间／本周进展”，可建议映射到负责人、任务或月计划、日期及周记录；一行混有计划与结果时分开呈现。
- 姓名相同、简称不唯一、日期含义不明时展示候选项；保留原值，不能直接覆盖为模型猜测。人员优先使用邮箱、工号或已确认的外部标识匹配，不自动创建可登录账号。
- 原表没有验收标准时保持待补充，不能编造标准。没有月计划关联的旧周报保留为历史暂存资料，允许管理者批量选择关系；不能为了入库而冒充临时任务或虚构月计划。
- “已完成”的原表状态与本系统“管理员已验收”分开。历史记录保留来源状态，未经明确确认不进入正式验收统计。归档项目、离职人员的历史事实也须能够保存，不冒充当前有效账号或项目。
- 默认批量生成草稿；已完成历史事项可作为历史资料查询导出，映射和确认完整后再进入相应业务范围。

### 3. 可核对、可重试的批量写入

- 预览明确列出新增、更新、跳过、冲突和待补充，更新显示前后差异。提交时再次检查权限、引用关系和数据版本。
- 来源系统、来源文件／表格、外部记录标识及导入批次形成追溯关系。仅凭姓名、标题或行号不能可靠去重；缺少稳定源标识时由内容匹配提出重复候选，交由用户确认。
- 同一请求重试返回原结果，同一来源重复导入不静默新增或覆盖。没有可靠键的记录不承诺任意改排后自动去重。
- 一次确认的关联数据在事务中提交，失败保留暂存资料并返回逐项原因。大表按已校验的依赖组分批，每批都有明确结果。
- 批次撤销采用有版本检查的反向变更；记录已被编辑、引用、发布或进入报告时阻止直接撤销，提供冲突清单和纠正流程。不能用整库恢复撤销一批导入而丢失之后其他人的填报。
- 解析文件和调用模型在事务外完成，复用现有领域权限与业务校验来写入。

### 4. 导出与升级迁移

- 业务导出：项目、年度目标、月计划、任务、周记录支持按月份、人员和项目导出 Excel／CSV；受当前身份可见范围限制。
- 可再导入的数据包：另提供带格式版本、稳定编号、关联关系和来源信息的 JSON 包。普通数据导出排除密码摘要、会话和服务密钥；受保护的整库备份仍用于灾难恢复。
- 表格导出保留记录编号和更新版本，支持离线填写后再导入比对。不能把修改后的 Excel 当作整库替换文件；完整恢复以已验证备份为准。
- 建立独立的数据格式版本及迁移登记。升级先备份，在副本执行转换，核对数量、编号、关系、关键字段及历史报告，再切换应用。
- 规则改动优先保留原始事实和稳定编号，通过字段映射、关系调整或有审计的转换更新数据。程序无法从原资料推导出的新增必填信息，只生成缺项清单。
- 回退必须考虑升级后的新增填报；不能简单承诺回滚旧备份仍保留全部新数据。迁移发布应控制写入窗口，恢复切换前核对新增数据处理方案。

### 5. 两个方向的 AI／API 接入

**系统调用模型解析：** 复用服务端模型地址和密钥配置，新增独立解析适配器；允许接企业模型或兼容接口。仅发送选定批次必要内容，密钥留在服务端。模型失败时可以人工映射继续处理，不丢失上传文件。

**外部智能体调用系统填报：** 建立版本化接口及接口文档，提供读取字段定义、查询本人可见的人员／项目候选、提交结构化导入草稿、校验预览、按授权确认导入和查询批次结果等能力。建议使用受限集成令牌，支持到期、撤销和请求去重，记录调用方与代表的用户身份。

网页、智能体、钉钉连接器共用上述导入规则。调用权限决定能否代表别人填报；提交草稿、导入确认、审核、发布和成果验收各自检查权限。模型输出本身不构成越过审核或扩大数据可见范围的授权。

钉钉在线表格、AI多维表、上传的 Excel 文件需要不同读取方式。钉钉官方 CLI 的[类型说明](https://github.com/DingTalk-Real-AI/dingtalk-workspace-cli/blob/main/skills/mono/references/intent-guide.md)对此作了区分；不能只凭一个表格链接就承诺全部类型可直接读取。直连实施前需确认实际表格类型与访问权限。

## 验收标准

1. 升级前后稳定编号、负责人、月周关系及历史报告保持可核对，成员无需重填已有事实。
2. 旧表不必先全部手工改成新模板；可保存缺项的解析草稿，只处理确有疑点的字段。
3. 同一文件重复提交、同一API请求超时重试不会生成重复数据；内容改变时展示差异。
4. 导入中断或校验失败后能继续处理，已保存资料和已确认匹配不会丢失。
5. 原表“已完成”不会自动计为管理者验收通过；月计划缺失不会被模型虚构补齐。
6. 错误批次能纠正；已有后续编辑或引用时明确提示冲突，不破坏其他人的新记录。
7. 导出后再导入可核对编号、日期和关系；普通导出不包含登录凭据。
8. 同名人员、归档项目、跨月记录、权限不足、模型失败与版本冲突都有明确处理结果。

建议先完成持久化迁移机制和统一导入导出，再扩展智能解析与钉钉直连；验收以实际历史样表及脱敏数据为依据。
