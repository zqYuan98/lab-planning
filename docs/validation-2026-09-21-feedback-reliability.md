# 问题反馈与使用可靠性第一期验收

2026-09-21 完成本地实现与验收；同日 09:45 已另行完成正式部署，见[上线记录](deployment-aliyun-feedback-2026-09-21.md)。本文保留本地开发时点的验证事实，范围承接[体验审查](usability-and-feedback-review-2026-09-20.md)中的第一批：反馈闭环、常用表单草稿、错误定位与完整消息历史。原有工作区变更保留，开发阶段未提交或推送 Git，也未访问正式数据库或发送真实外部消息。

## 已实现

| 用户需要完成的事情 | 实际行为 |
| --- | --- |
| 随时提出问题或建议 | 顶部和侧栏常驻入口，独立抽屉保留底层工作页面；描述加可选截图，支持粘贴、拖入、选择、预览、删除 |
| 知道问题交给谁、处理到哪里 | 提交回执显示受理人；列表、详情时间线和站内消息提供进度；管理者可改派、请求补充、暂缓复查 |
| 确认修复真正可用 | 管理者必须填写解决说明、可验证版本并确认已上线；提报人确认解决或带原因重开；管理者结案另记原因 |
| 避免重复问题各自失联 | 关联主反馈后回告可验证版本，保留各自验证结果与权限；主单确认不会覆盖子单验证失败 |
| 受理人不可用时有人接手 | 读页面明确标注不可用受理人；后续写操作原子改派给可用管理者并留痕、通知；无人可接手则明确报错并保留输入 |
| 写到一半或失败后继续 | 月目标、周安排、周进展、工作清单与反馈草稿按账号、对象隔离；多选、取消勾选及条件字段可恢复 |
| 知道失败后怎么办 | API 定位编号贯通响应、页面和异常日志；反馈可附编号；网络中断保留输入；登录过期可重新认证并恢复草稿 |
| 避免成功保存后重复创建 | 已成功写入但刷新失败时，禁用重复保存，只提供重新读取已保存结果；反馈写命令另有幂等凭据 |
| 找到早期消息和未确认安排 | 服务端先按权限、未查看或待确认筛选，再游标分页；全量计数；查看消息不替代确认安排 |

截图每次操作最多 3 张，单张 2 MiB，仅 PNG/JPEG/静态 WebP。前端实际解码，后端校验容器、大小、维度及结构，PNG 另校验 CRC 和解压行数据；后端 JPEG/WebP 校验不等于完整像素解码。附件受登录和反馈权限保护，不进入常规业务导出。本期反馈仅使用站内通知，误入外发队列也会被工作进程拦截。

普通业务草稿保留于当前标签页，期限 7 天；反馈文字与截图保留于当前浏览器，期限 14 天。草稿不会自动成为正式提交，存储不可用时会提示。临时草稿不是服务端备份；反馈正式记录、截图、历史和幂等凭据包含于整库 SQLite 备份。
