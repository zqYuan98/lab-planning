# 使用与运行指南

## 首次上线范围

首版面向单个部门、单实例运行，覆盖管理者与成员账号、部门项目和归档、独立年度目标、月度目标管理与审核合并发布、个人任务与周记录、月度成果确认，以及可保存、定稿、导出的管理者报告。首次上线从空数据开始，成员自行注册并经管理者审批，由管理者建立项目，再从一个月份开始建立目标和执行。

历史公司数据库、文件和账号不会自动导入。现在可在“数据导入”上传历史表格、图片或粘贴文字，配置模型后解析、校对并保存。自动报告需要管理者主动启用，AI 润色在报告页手动触发。

## 日常流程

### 随手记录与向上汇报

侧栏「我的工作清单」持续展示本人在手事项，管理者也可用它安排自己的工作。点击「新建任务」，把领导一次交办的内容按一行一件事粘贴，预览后保存；交办人、日期和截止要求可以补充，截止未知时保留「待确认」。清单可切换领导交办、待安排、本周推进、待反馈和已完成，并记录预期交付、当前进展、下一步、优先级、预计剩余投入及需要领导决策的事项。

「安排本周」将原任务带入周计划；换周、换月不会从在手清单移除未完成任务，也不会复制出另一件任务。已有正式任务可以补录领导交办来源，任务纳入月度目标后仍保留交办信息。总体完成与本周完成分别记录。

汇报时点击「汇报进度」，展示当前筛选范围的清单，或导出 Excel 可打开的 CSV、打印为 PDF。预览和导出使用同一份当时快照，包含尚未排期的事项；与报告中心的正式周报/月报分别使用。只有本人清单进入此预览，不创建公开分享链接。

### 计划与交付

1. 管理者建立月度目标，填写项目或工作类别、预期成果、负责人、参与人员、日期与验收标准，管理者确认后发布。成员可通过“新增临时目标”提报本人负责的临时事项，可补充来源背景，提交管理员审核发布；本人草稿或退回项可修改。临时目标按月记录阶段成果，未完成时由管理员跨月承接，保留临时标记与来源。已有提报支持审核、退回和合并，来源历史保留。
2. 成员从自己参与的月度目标点击“关联个人任务”，填写个人交付；项目和人员通过目标关联，无须重复指定。普通成员仅能查看自己的个人任务和周记录，目标负责人也不能读取其他成员的个人工作。
3. 在页面显示的截止时间前，分别正式提交“本周完成情况”和“下周计划”。新规则默认当周最后工作日北京时间 **16:00 前**，内置 2026 年国家节假日与调休，企业例外优先；原来没有截止政策的旧规则从下一完整周采用新默认，已经保存的政策及周期截止保留。全休周无提报义务，详见[假期与调休截止说明](holiday-weekly-deadlines.md)。先更新周记录，再核对整份内容并提交；仅保存草稿或单条周记录不代表已完成整份提报。本周仍在推进的任务可以如实填写进展，无须提前标为完成。适用审核周期的成员下周计划整份提交后，由管理者通过或填写意见退回；成员按意见修改后重新整份提交，保留各次版本。
4. 系统保留截止未交事实，补交显示实际时间；后续修改需再次提交形成新版本。管理员可按状态和应交项筛选，代录、豁免及更正须填写原因并留痕。首次启用从下一个完整周开始，周中加入的成员从下周计入；历史名单不确定时先由管理员核对。
5. 管理者确认月度成果，并在报告中心生成、编辑、导出和定稿周报/月报。周提报情况作为独立管理记录，旧报告快照不随补交或目标变化。

周提报暂停与恢复从下周生效，保留原周期记录；服务重启后自动补查生效周期的遗漏。截止时间按服务端时间计算，16:00 整点提交记为逾期。当前不增加日计划。有关联目标的周草稿可在目标发布前保存，正式提交须满足目标已发布等校验；可为临时工作补充来源背景。

计划审核与提交时效分别记录：等待审核、退回修改及审核通过不会改变原按时或迟交事实。已批准内容修改后，变更条目等待重审，未变更条目的批准继续有效；补充执行进展、成果或证据不要求重新审核计划。管理员正式下发的安排视为已确认，代录和下发草稿仍按规则审核。

管理员可填写原因删除单条周安排，保留原任务、其他周安排和历史提交、报告。删除后可沿用原任务在同一周重新安排；需要补关联月度目标时，先调整原任务关联，再建立新周安排。审核从下一个完整提报周期启用，覆盖该周期的下周计划；暂停与恢复同样从下个完整周期生效，历史暂停周期不补审。操作步骤与边界见[周计划审核与留痕删除](weekly-plan-review-and-deletion.md)。已于 2026-09-21 上线：删除功能立即可用，审核从 2026-09-28 提报周期开始，覆盖 2026-10-05 起的下周计划；详见[上线记录](archive/deployment-aliyun-weekly-review-2026-09-21.md)。

成员停用后不能登录或接收新工作，日常成员、部门概览和周计划默认隐藏该成员，可主动勾选“包含停用成员”查看历史。没有业务或历史关联的账号可在成员管理中确认删除；有业务关联时显示具体原因并保留原责任归属。详见[成员账号管理](member-accounts.md)。

站内消息记录正式月度发布、管理者下发安排、重要变更和周提报提醒；系统查看、确认接收和正式提交分别记录。系统支持钉钉企业内部 H5、身份绑定和工作通知，实际启用范围由部署环境和管理员试点设置共同决定。通用配置与验收步骤见[钉钉接入与公网服务器部署](dingtalk-public-server.md)。

「进展与催办」提供任务进展、明确回应、批量催办、阻塞支持与延期审批。钉钉原生待办、互动卡片、机器人和组织事件均须按渠道单独配置并完成企业验收后启用。日常操作与启用步骤见[平台与钉钉协作说明](dingtalk-collaboration-operations.md)。

「进展与催办」的全部事项是跨周期任务总台账：管理者查看全员，成员查看本人，包含历史和已完成任务。卡片分别展示整个任务与当前/最近周记录的状态。只完成本周阶段不会自动结束整个任务；全部工作结束时，在周进展中明确勾选“同时完成整个任务”，任务和周状态会一起保存。此操作不替代月度验收或整份周提报。范围与状态修正见[验证记录](archive/validation-2026-09-20-followup-status.md)。

有关联月计划的周记录，包括未提交草稿，所属周都须与月计划月份相交；系统按周一至周日判断，因此跨月交界周可以关联相交的月份。跨月延续时，先由管理者建立承接月度目标并完成审核发布，再由管理者调整原任务的月计划关联，最后建立目标周记录。已提交历史周记录保留原月归属；管理者调整关联时，符合目标月份的既有未提交草稿会同步调整归属并留下变更记录。

## 正式运行

```sh
npm ci --include=dev
npm run build
npm start
```

打开 http://127.0.0.1:4310 。生产运行由一个服务提供网页和 API。裸机可复制 `.env.example` 为 `.env`，将其中的 `NODE_ENV` 改为 `production`，再设置监听地址、端口、数据路径及可选 AI；真实 `.env` 和数据库已加入 Git 忽略。

外网部署时使用 HTTPS 反向代理，配置 `APP_ORIGIN` 为实际站点地址、`COOKIE_SECURE=true`，数据目录必须挂载持久卷。仅在受控首次初始化时开放创建管理员页面，完成初始化后再开放给成员。

正式服务器建议使用仓库提供的 Compose 配置，完整初始化、HTTPS、可信代理、备份和迁移步骤见 [部署手册](deployment.md)。

```sh
cp deploy/production.env.example .env
docker compose config --quiet
docker compose up -d --build
```

Compose 固定容器内 `HOST=0.0.0.0` 与生产模式，服务器只映射 `127.0.0.1:4310`，初始化通过受控SSH隧道进行。正式使用前需按手册切换HTTPS。当前架构适合单实例的小型部门应用；多副本部署前需迁移存储和共享会话方案。

## 汇报自动生成与 AI

无需 AI 密钥即可生成包含数据统计、实际成果、阻塞、变更和下期安排的中文报告。报告中心可配置自动草稿生成，默认关闭，时区为上海；只有启用后才按设定周期执行，同周期自动任务持久去重，不自动对外发送消息。

周报在设定的星期和时间生成该周草稿；月报选择月末最后一天时生成当月，选择每月 1 至 28 日时生成上月。服务须在触发日运行：若在同一天的设定时间后启动，会执行当日到期任务；如果停机跨过整个触发日，恢复后不会补跑错过的周期，可在报告中心选择该周期手动生成。

如需 AI 润色，在服务端配置 `AI_BASE_URL`、`AI_MODEL`、`AI_API_KEY`，再显式使用报告页的润色功能。该动作会将报告事实发送给配置的服务商；统计表和快照不会由模型改写。未配置时仍可完成生成、人工编辑、归档和导出。

## 备份与恢复

业务资料支持 Excel／CSV 导出和带版本的 JSON 迁移包；JSON 恢复需预览、匹配现有账号并确认，无冲突时保留原编号、版本、历史和报告快照。详细用法见[智能导入与数据迁移](intelligent-import.md)。

```sh
npm run backup
```

脚本使用 SQLite 在线备份接口，并检查备份完整性；可在命令后指定新的输出文件路径。备份包含账号、业务数据、原始上传资料、历史、报告和模型配置（包括密钥），应与数据库一样妥善保管。业务 JSON 包不包含原始附件、账号密码或系统配置；迁移完整运行状态时使用整库备份。

恢复时先停止应用，保留当前数据库及 WAL 文件的副本，在新的目录放置已验证备份。**恢复、克隆或回退整库后，启动应用前必须执行 `npm run reset-operation-context -- <恢复副本的路径>`**，使恢复点之后的旧浏览器承接请求失效；普通重启和正常应用升级不执行此命令。随后将 `DATABASE_PATH` 指向该副本，先在独立实例核验账号、计划和报告，再切换正式实例。容器命令见[部署手册](deployment.md)。业务 JSON 恢复实际写入数据时由事务自动更新操作环境。

## 团队自主注册

员工在登录页选择“申请加入团队”，填写姓名、邮箱、岗位（选填）并自行设置密码。密码至少8位，允许8位纯数字，不强制复杂度。管理者在“成员管理 → 注册申请”通过或驳回；通过后启用普通成员账号，驳回需填写原因，也可再次审核。

申请通过前不能登录、查看部门数据或被分配任务。已存在的邮箱不能重复注册或覆盖密码，旧账号按原方式登录。上线与验证记录见 [2026-09-09 注册功能更新](archive/deployment-37-2026-09-09-registration.md)。
