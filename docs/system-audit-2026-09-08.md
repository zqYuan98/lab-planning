## 结论与范围

本次审查覆盖当前 `lab-planning` 应用的登录权限、月计划提报/审核/发布、周执行及跨月承接、报告与快照、搜索导航、数据库事务、生产启动与部署配置。发现的可复现问题已修复，并增加对应回归测试。左上角已去掉“人工智能实验室”副标题，保留天枢实验室品牌；报告部门名称不受影响。

系统适合一个部门、一个应用实例的小范围试运行。代码验收与正式服务器上线是两件事：当前办公电脑上的本机预览不等于已完成部门网络部署。本次未做真实业务量压力测试、外部渗透测试、旧系统迁移，也未配置实际服务器域名、证书或备份计划。

## 当前有哪些服务

| 组件 | 当前实际状态 | 正式部署方式 |
|---|---|---|
| 网页与 API | 一个 Node.js / Express 进程，监听 `127.0.0.1:4310`，提供 React 构建产物及 API | 一份应用容器，持久挂载数据卷 |
| 数据库 | 本地 `data/lab-planning.sqlite`，SQLite WAL 模式 | 无独立数据库服务；使用本机磁盘或容器命名卷 |
| 自动报告草稿 | 与 API 同进程，每30秒检查；当前设置关闭 | 管理者在报告中心启用；需要进程常驻 |
| AI 润色 | 当前未配置；规则生成和 Word 导出不受影响 | 可选外部 API，配置后手动触发 |
| HTTPS / 开机托管 / 异机备份 | 当前本机预览没有这些生产运维设施 | Nginx + Compose 重启策略 + 运维备份任务 |

生产运行不需要单独启动 Vite，也不需要 Java、MySQL、Redis、Office 或 LibreOffice。完整步骤见 [部署手册](deployment.md)。

## 已修复问题

P1 表示可能破坏权限或历史事实的高优先级问题；P2 表示业务正确性或运行可靠性问题；P3 表示错误处理问题。级别用于本项目修复排序，不是外部安全认证。

| 级别 | 原问题及触发条件 | 修复后的行为 |
|---|---|---|
| P1 | 首次初始化可接受伪造的 Host 与同源 Origin | 未配置域名时限制本机 Host；配置后严格校验访问来源 |
| P1 | 已提交周记录撤回后，任务跨月改关联会改写原月份 | 根据历史提交事件保留原月归属，未提交草稿按规则调整 |
| P2 | 原月协作者在任务移入新私有计划后，失去历史任务说明 | 返回其有权查看的历史任务快照，不暴露新私有安排 |
| P2 | 直接传 `sourcePlanId` 可绕过跨月承接的负责人/合并限制 | 统一校验来源权限和状态，禁止重新承接已合并来源 |
| P2 | 停用协作者导致正常编辑失败，或被表单无意移除 | 保留既有责任记录，禁止新增停用成员为协作者 |
| P2 | 已归档项目的待审提报进入发布批次，阻止正常计划发布 | 新发布/合并/周任务候选排除归档项目，保留历史浏览 |
| P2 | 跨月或后来补关联的报告源事实只显示编号，缺少原计划名称 | 冻结引用计划上下文，显示原月份与名称，不扩大统计分母 |
| P2 | 搜索历史周承诺后跳到错误周；不同周关键词被拼成误匹配 | 按实际匹配周定位，只在同一记录内匹配 |
| P2 | 已退回的提交不计入概览审核分母 | 将退回提交纳入，未提交草稿仍排除 |
| P2 | AI 返回空白正文时覆盖已保存草稿 | 拒绝空白结果，保留原正文、版本和审计；并发保存/定稿仍受保护 |
| P2 | 成功登录清除失败限额，代理后不同客户端共用限额 | 成功登录不清除失败计数；仅信任显式代理 IP/CIDR |
| P2 | 初始化或会话写入失败留下部分账户状态 | 用户、审计及会话轮换按事务提交，失败完整回滚 |
| P2 | 被拒绝的异步事务仍可在回滚后写入；忙锁掩盖真实错误 | 拒绝失效事务上下文访问；锁冲突返回可重试的503 |
| P2 | 端口被占用仍打印“系统已启动” | 仅监听成功后启动定时检查并报告就绪，失败退出码为1 |
| P2 | 备份可能进入 Docker 构建上下文；裸机生产安装漏装启动依赖 | 数据库被构建规则排除；文档使用仓库外备份和 `--include=dev` |
| P3 | 非法 JSON 的错误响应反射请求原文 | 返回固定格式错误，不回显提交内容 |

另外验证了失效会话、危险代理配置、版本冲突、普通成员权限、报告定稿保护、自动草稿周期去重，以及报告中英文和 Word 内容的来源一致性。

## 仍需明确的使用与运维边界

1. **单部门、单实例。** 目前 SQLite 与进程内限流适合此范围；没有多实例协调或故障自动切换，登录失败限流会随进程重启重置。不要直接扩容多个副本。
2. **自动生成的是草稿。** 管理者仍须确认事实和管理判断。停机跨过整个触发日不会补跑，需手动补生成；不会自动向外发送消息。
3. **备份需安排。** 已有在线备份脚本，但没有替运维创建定期任务。需确定频率、保留期、异机位置，并做恢复演练。
4. **账号是本系统账号。** 由管理者创建和调整，尚未接入企业 SSO。第一次初始化应在受控入口完成。
5. **AI 尚未做真实服务商联调。** 已验证模拟成功、失败、空白结果和并发保护；实际模型配置、连通性与内容效果在选定服务商后验收。
6. **正式网络入口未配置。** 已提供 Nginx 与 Compose 模板；实际服务器需要配置域名/证书、可信代理、访问范围、日志与备份。当前本机4310仅能本机访问。

建议先让少量成员用一个实际月份跑完“提报 → 审核整理 → 发布 → 每周填报 → 月度验收 → 报告定稿”，再扩大使用。年度目标继续独立记录，月度与每周的关联保持必需业务链路，临时工作按现有规则明确记录原因。
