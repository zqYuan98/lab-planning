# 清爽现代 B 端工作区 UI 重构设计规格

日期：2026-09-22  
状态：方案 A 已实现并通过本地验收  
范围：整体 UI 重构；不修改业务逻辑、数据口径、API、权限或工作流

## 1. 目标与参考

以用户提供的以下两张参考图为视觉基准：

- `C:/Users/24830/Downloads/天枢实验室部门概览页清爽现代B端美化设计.png`
- `C:/Users/24830/Downloads/天枢实验室我的工作清单页清爽现代B端美化设计.png`

建立一套统一的清爽现代 B 端界面：深海军蓝导航、浅蓝灰画布、白色内容面板、品牌蓝主操作和克制的语义色。重点提升全局壳层、部门概览和我的工作清单的层级、留白、可扫读性及操作聚焦，同时让其他业务页通过共享变量、按钮、表单和文字色阶自然继承同一视觉语言。

本次只调整结构化展示与样式。现有数据来源、计算结果、筛选条件、点击行为、提报/审核/保存规则和接口参数全部保持不变。参考图中的文案、数量和示例状态不作为业务需求。

## 2. 设计原则

1. **统一而不过度装饰**：白底与浅灰蓝卡片承担层级，品牌蓝只用于主要操作、选中态和关键链接。
2. **深色文字优先**：标题、正文和元数据用明确的深浅三级色阶；不使用大面积低对比灰字模拟“高级感”。
3. **信息密度可控**：增加区块间距和行内呼吸感，但不隐藏现有字段或降低一屏可见的有效任务量。
4. **颜色具有含义**：蓝、红、琥珀、绿、紫分别承担信息、风险、提醒、完成和特殊类型；颜色必须同时配合文字或图标。
5. **动效服务反馈**：仅在悬停、按压、展开和状态切换时使用短促动效，不让列表内容持续漂移或闪烁。

## 3. 全局视觉系统

### 3.1 色彩

| 用途 | 建议值 | 使用规则 |
| --- | --- | --- |
| 品牌蓝 | `#1769E8` | 主按钮、选中态、关键链接、焦点色 |
| 品牌蓝悬停 | `#0F5DD7` | 主按钮 hover |
| 深海军蓝导航 | `#08203A` → `#0A2B50` | 侧栏纵向轻渐变 |
| 页面画布 | `#F4F7FB` | 工作区背景，可叠加极弱蓝色光晕 |
| 一级表面 | `#FFFFFF` | 面板、表格、任务卡 |
| 二级表面 | `#F8FAFD` | 筛选区、表头、弱信息区 |
| 主标题 | `#0D2344` | 页面标题、数字、任务标题 |
| 正文 | `#29415F` | 正文、字段值、主要说明 |
| 次级文字 | `#5D708A` | 日期、来源、辅助说明 |
| 占位/禁用 | `#8290A3` | 仅限占位符和禁用内容 |
| 分隔线 | `#E3EAF3` | 面板、表格与输入边框 |

危险、警告、成功和紫色类型沿用现有语义，只降低背景饱和度并保证文本对比度。不得把可操作文字或业务事实降到占位色。

### 3.2 字体与层级

- 继续使用系统中文字体栈，不引入远程字体依赖。
- 页面标题：桌面 `32px/1.2`、700；窄屏 `26px`。
- 页面副标题：`14px/1.7`、正文或次级色。
- 指标数字：桌面 `40–44px/1.1`、700；移动端 `30–34px`；使用等宽数字特性。
- 区块标题：`16px`、650；任务标题：`15–16px`、650。
- 正文：`13–14px/1.7`；元数据不低于 `12px/1.6`。
- 英文 eyebrow 不再作为主要视觉元素；保留时应弱化，不能与中文标题争夺注意力。

### 3.3 圆角、边框和阴影

- 主面板、指标卡：`14–16px` 圆角。
- 控件、按钮：`9–10px` 圆角；标签：`6–8px` 圆角；选项卡组可使用胶囊形底座。
- 面板使用 `1px` 冷灰蓝边框；常态阴影控制在 `0 8px 24px rgba(24, 56, 96, .06)` 以内。
- 不使用粗重投影、玻璃拟态或多层发光。指标图标允许单层浅色光晕。

### 3.4 间距

- 桌面工作区水平内边距 `32–40px`，区块纵向间距 `24–30px`。
- 页头标题与操作对齐；页头到指标区 `28–32px`。
- 面板内部采用 `12 / 16 / 20 / 24px` 节奏。
- 超宽屏将内容最大宽度从现有 `1360px` 提升到约 `1680–1760px`，并保持水平居中，避免参考图式宽表格被过度压缩。

## 4. 全局壳层

### 4.1 侧栏

- 桌面宽度调整为 `252px`，折叠宽度为 `76px`，与参考图的品牌区和导航留白一致。
- 使用深海军蓝背景；品牌区增加上下留白，现有 Logo 与名称保持不变。
- 导航分组标题使用较亮的蓝灰色，菜单文字达到清晰对比。
- 激活项使用明亮品牌蓝渐变底、白色文字和图标，并保留左侧 `3px` 高亮线；hover 使用深蓝抬升层。
- 未读数字徽标保留现有含义，视觉改为高对比蓝色圆形徽标。
- 折叠侧栏和移动抽屉继续使用现有状态与键盘逻辑。

### 4.2 顶栏

- 保持现有面包屑、全局搜索、反馈入口、月度审核/本周安排和账号菜单行为。
- 顶栏高度维持约 `68–72px`，白底、底部细边框和极轻阴影。
- 搜索框使用浅蓝灰底、`10px` 圆角，焦点时转白底并显示品牌蓝焦点环。
- 主要操作维持实心品牌蓝，账号区与通知/反馈入口保持简洁，避免多个同权重蓝色按钮。

### 4.3 画布与共享控件

- 页面画布改为统一浅蓝灰底，可用纯 CSS 添加局部低透明度蓝色径向渐变，不新增图片资源。
- 全局按钮、输入框、选择器、弹窗、空状态继承统一圆角、边框和文字色阶。
- 使用现有 Lucide 图标和品牌图形；本次无需 image2 生成资源。只有未来新增插画型空状态时再使用生成图片。

## 5. 部门概览页

### 5.1 页头与操作区

- 标题左侧增加 `48px` 浅蓝图标底座，使用现有概览类 Lucide 图标；标题、副标题组成明确的两行层级。
- 周期选项、日期操作、月度目标和安排任务置于页头右侧，按照“筛选在前、操作在后”排列。
- `安排任务` 为主按钮；`月度目标` 为次按钮。现有跳转参数与行为不变。
- 中等宽度允许控制区换行；移动端标题和操作纵向排列，主次按钮并排或等宽。

### 5.2 六项指标卡

- 保留现有六项指标、数值、说明、点击下钻和选中规则，不照搬参考图中的示例数据。
- 桌面采用六列；不足宽度时依次降为三列、两列、单列。
- 每张卡使用独立白底至浅语义色渐变、细语义边框、圆形图标芯片与右下角纯 CSS 半圆装饰。
- 数字为卡片第一视觉焦点；标签在上、数字居中段、说明在下。卡片最小高度统一，说明不因内容长短导致数字基线错位。
- hover 只轻微上移 `1–2px` 并增强边框；选中态使用语义色描边和浅内环，不能仅靠背景色区分。

### 5.3 工作空间、选项卡与筛选

- 多维工作空间使用单一白色大面板，`16px` 圆角；选项卡、筛选器、结果摘要和内容区通过细分隔线组织。
- 选项卡使用圆润底座和明确蓝色选中态；保留全部现有视图与移动端视图选择器。
- 搜索和筛选字段高度统一为 `38–40px`；风险筛选、包含停用成员、保存视图等现有控件全部保留。
- 激活筛选标签采用浅蓝胶囊，清除按钮仍可键盘操作；展开筛选继续使用现有状态。

### 5.4 表格与其他视图

- 表头采用浅蓝灰底和深色字重；行高增至适合长列表阅读的舒适密度，同时保留现有紧凑模式。
- 成员、任务、看板、项目和时间排期视图不改变列、排序、下钻或操作。
- 任务预览中的优先级、类型和状态标签降低饱和度；优先级仍通过左侧色条、文字和标签共同表达。
- 表格行 hover 使用极浅蓝底，不使用斑马纹干扰长文本；冻结/滚动行为保持现状。

## 6. 我的工作清单页

### 6.1 页头与操作区

- 标题左侧增加与概览页一致的 `48px` 图标底座，使用清单类 Lucide 图标。
- `汇报预览` 视觉文案可显示为“汇报进度”，但触发的仍是现有预览流程；`快速记录` 可显示为“新建任务”，但仍打开现有记录弹窗。若不更改文案，则至少按参考图提升主次层级。
- 次操作为白底描边按钮，主操作为品牌蓝实心按钮；两者放置在标题区右侧并保持 `44–48px` 高度。

### 6.2 四项指标卡

- 本轮保持现有四项统计的数据口径、点击筛选与不可点击项：`在手事项 / 高优先级 / 待安排 / 待协调`。
- 不直接替换为参考图中的 `待处理 / 逾期 / 本周到期 / 已完成`，因为现有四张卡的数值并不对应这些含义；若未来需要替换，应作为独立业务需求定义计算与筛选规则。
- 视觉采用蓝、红、琥珀、紫四种克制语义色；数字 `40–44px`，圆形图标芯片，右下角半圆装饰，卡片高度一致。
- 可点击卡保持 `button`、`aria-pressed` 和现有筛选行为；待协调的静态卡不得伪装成可点击按钮。

### 6.3 选项卡、搜索与筛选

- 工作区作为一个白色大面板。第一行放视图选项卡和搜索，第二行放优先级/类型筛选及筛选说明。
- 选项卡采用胶囊选中态，数量紧跟标签并降低权重；不得删除或合并现有视图。
- 搜索框桌面宽约 `280–330px`，小屏占满；筛选器使用圆润白底控件，保持原有选项和值。
- `TaskLegend` 保留渐进披露，不常驻展开占据列表空间。

### 6.4 任务列表

- 列表使用独立浅边框任务卡，卡间距 `10–12px`；卡片内部桌面维持“事项 / 进展 / 安排与操作”三列语义。
- 优先级使用左侧 `3px` 色条；卡片背景以白色为主，高优先级或逾期只允许极弱的暖色渐变。
- 标签背景降饱和、文字对比提升；优先级、工作类型和状态继续同时显示，顺序不变。
- 标题、来源、截止日期、当前进展、下一步、协调/支持信息和现有操作全部保留；长文本最多通过现有折叠说明控制，不新增数据截断。
- 行操作中的安排按钮保持次按钮，编辑/查看使用文字操作；状态说明与按钮分开，避免灰字看似禁用。
- 空状态、刷新失败、待核对提示继续使用现有逻辑，只同步新版表面与文字色阶。

## 7. 动效与交互反馈

- hover/press/focus 反馈时长 `160–200ms`，使用 ease-out；卡片最多上移 `2px`。
- 按钮按压可缩放至 `.98`；箭头类图标 hover 平移不超过 `3px`。
- 筛选、切换视图和数据刷新不对整页或列表使用入场动画。
- `prefers-reduced-motion: reduce` 下取消位移和缩放，只保留颜色变化。
- 键盘输入模式下保持现有立即反馈策略，不引入延迟动画。

## 8. 响应式规则

| 视口 | 预期布局 |
| --- | --- |
| `≥1440px` | 扩展内容宽度；概览六列指标；工作清单四列指标；工作列表三列 |
| `1024–1439px` | 概览三列或六列自适应；清单四列或两列；复杂工具栏可换行 |
| `768–1023px` | 侧栏进入现有移动模式；指标两列；页头操作换行；任务操作下沉 |
| `421–767px` | 两列指标；搜索与筛选占满；任务卡改为单列；按钮保持至少 `44px` 点击高度 |
| `320–420px` | 单列指标；页头操作等宽堆叠；控件不溢出；表格仅在自身容器横向滚动 |

所有断点必须保证页面根节点无水平滚动条，抽屉、弹窗和表格滚动区域除外。

## 9. 可访问性

- 正文和重要元数据达到 WCAG AA 对比度；占位色只用于 placeholder/disabled。
- 交互控件保留语义元素、现有 `aria-label`、`aria-pressed`、live region 和键盘行为。
- 所有焦点态使用 `2px` 品牌蓝轮廓与可见偏移；深色导航使用更亮的蓝青焦点色。
- 颜色不能独立传递优先级、类型、风险或状态，必须有文字/图标/边线中的至少一种补充。
- 图标装饰标记 `aria-hidden`；图标按钮必须保留可读标签。
- 触控目标最小 `44×44px`；桌面紧凑文字操作至少保持足够行高和焦点区域。

## 12. 自审与现有实现冲突

1. 当前样式由 `theme.css → workspace-shell.css → workspace-tech.css → workspace-saas.css` 依次导入，且页面 CSS 在组件加载时加入。多个文件重复定义标题、指标和响应式规则，存在特异性和导入顺序冲突。实现时应把最终共享视觉收敛到 `workspace-saas.css`，页面结构细节留在各自页面 CSS，避免继续追加同权重重复规则。
2. `workspace-shell.css` 原先将主内容限制为 `1360px`，与参考图的宽阔表格布局冲突；核心两页扩大至约 `1800px`，并同步使用新的 `252/76px` 侧栏宽度与折叠计算。
3. 工作清单基础 CSS 将指标定义为三列，后续 SaaS 覆盖改为四列。应将基础定义同步为四列或删除重复网格定义，防止样式加载和断点下回退为错误列数。
4. 参考图希望四项指标为“待处理/逾期/本周到期/已完成”，现有实现的数据口径是“在手事项/高优先级/待安排/待协调”。本轮明确不改业务逻辑，因此保留现有口径，只复刻视觉层级；不能只改标签导致数值与含义不符。
5. 当前标题组件未提供参考图中的图标底座。可在两页添加纯展示结构或扩展 `PageHeader` 的可选 icon 插槽，但不得影响其他页面；优先使用页面级 class，避免全站标题被意外改变。
6. 当前存在多处 `12px` 灰色元数据，这是用户认为“像 AI 生成”的主要观感来源。解决方式是提高对比度、减少不必要灰阶、用间距与字重建立层级，而不是把所有辅助文字改成品牌蓝。
7. 现有任务卡已用左侧优先级色条、文本标签和语义状态，本次应复用这些语义类，避免增加第二套优先级映射。
