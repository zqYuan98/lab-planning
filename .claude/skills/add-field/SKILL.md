# 新增字段

这个系统的表单是一个字段一个字段长大的：工作事项编辑框曾有 16 个始终可见的字段。每个字段单独看都合理，合在一起没人愿意填。新增前按下面的顺序过一遍。

## 1. 三个问题

1. **谁填，多久填一次？** 每周都要填的字段，成本乘以人数乘以周数。
2. **谁读，读了之后做什么？** 没有人据此做决定的字段不加。
3. **能不能从已有数据得到？** 能算出来、能从上一条带过来、能由 AI 从一句话里提取的，不让人手填。

三个问题有一个答不上来，就不加，把原始需求退回去问清楚。

## 2. 放在哪里

- 默认可见字段已满 8 个时，新字段进收起的分组，或者替换掉一个使用率低的字段。
- 必填字段不进收起分组。只在某个状态下需要的字段，在那个状态出现时才显示。
- 只为审计、追溯存在的信息（原因、来源、版本）记录在历史里，不放在主表单和列表上。

## 3. 落地清单

- 类型和长度限制写进 `shared/entity-rules.ts`，表单、服务端校验、迁移包都从这里读。
- 服务端校验和权限：角色判断走 `server/authorization.ts`。
- 数据导出 / 恢复包的 schema 同步（`server/data-transfer-schema.ts` 有编译期一致性检查）。
- 列表和卡片默认不显示新字段；确实要显示时，遵守“一个条目最多 3 个标签”。
- 测试：保存、读取、导出恢复各一条。

## 4. 同时考虑删掉什么

每加一个字段，看一眼同一个表单里有没有可以合并或下线的字段，在说明里写出来。
