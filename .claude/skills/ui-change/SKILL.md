# 修改界面

## 1. 先写清楚任务

用一句话写出：谁，在哪个页面，要完成什么，现在哪里不顺。例如“成员在每周执行页更新一条进展，要先滚过八段规则说明才看到自己的记录”。写不出来就先问提出需求的人，不要开始改。

“更现代”“更有科技感”“更好看”不是任务。遇到这类要求，先问清楚哪个页面的哪个操作让人不舒服。

## 2. 读规范，量现状

- 读 `design-system/lab-workspace/MASTER.md`。
- 运行 `npm run lint:design`，记下当前计数。
- 对要改的页面截图：1440px 和 375px，各一张整页。

## 3. 改

- 字号、字重、圆角只用 `src/tokens.css` 的变量。缺一个刻度时先改 MASTER.md 说明理由，再加变量。
- 颜色引用已有变量，不写新的色值。
- 改一条样式，就去它定义的地方改。同一个选择器在多个文件里重复定义时，合并到一处并删掉其余的，不要再追加一条优先级更高的。
- 不新建“覆盖层”样式文件。
- 说明文字放进收起的 `<details>`；内部编号、版本号不上列表。
- 文案写“是什么、下一步做什么”。

## 4. 验证

1. `npm run lint:design`：硬规则为 0，各项计数不高于基线。计数下降时运行 `node scripts/design-lint.mjs --update`。
2. `npm test` 和 `npm run build`。
3. 同样的视口再截一次图，和第 2 步并排看：有没有溢出、错位、被截断的文字、看不清的对比度。
4. 用第 1 步写的任务实际操作一遍，数一数点击次数和需要阅读的文字量，和改之前比。

## 5. 提交说明里写

- 第 1 步的那句任务描述。
- 前后截图。
- 删掉了什么（规则、文件、字段、文案）。
- 没验证的部分。

## 不要做

- 不要为了“统一风格”一次改所有页面。一个页面一个提交。
- 不要引入新的 UI 库、图标库、字体或动画库。
- 不要用测试断言样式源码里的字符串；那样的测试只会阻止重构。
